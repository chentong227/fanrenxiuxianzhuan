# 美术与体验总纲（v2 统筹）

> 本文是整个游戏视觉与体验改造的"宪法"。后续所有 UI/美术/演出改动须与此一致。
> 配套阅读：authenticity-design.md（玩法真实感标尺）。

## 〇、考据方法论红线（2026-06-11 用户裁决，适用于一切设计/剧情/美术调研）

1. **多方证据交叉验证**：任何剧情节点立项前 ≥2 个独立来源吻合方可定稿；
   单源信息一律标"待证"。逐集剧评/分集梗概的证据力 > 人物百科（百科常混编小说设定）。
2. **严格区分小说线与动漫线**：动漫为唯一正典，小说仅作背景补充——
   检索结果须先判定它描述的是哪个版本，再决定可否采用。
3. **事故记录（引以为戒）**：欧阳飞天战（原著线误入嘉元城）；陈巧倩"筑基无望"
   （与已筑基事实相反）；青元剑诀"血色禁地得书页"（误传）；大衍诀"无名卧底"
   （动漫线：叶师叔本人即千竹教卧底，篇末为雷万鹤所杀——此两点动漫与小说无出入）。

## 一、气质定位

《凡人修仙传》的味道不是"炫光仙侠"，是**苍凉、孤独、克制、凶险**：
一个资质平庸的少年，在烛光药庐里一坐就是数月，在深山里步步算计。

因此视觉基调定为：**"夜读残卷"** ——

- **墨纸黑**：背景如夜里摊开的旧宣纸，黑中带暖（不是科技感的冷灰蓝）。
- **烛光金**：高亮、标题、贵重之物，是烛焰与铜器的暖金，克制使用。
- **黛青远山**：主交互色（按钮/链接/生机），青绿偏灰，如远山如青瓷。
- **朱砂红**：危险、心魔、战斗。印章用色。
- 全局蒙一层极淡的**纸纹颗粒**，面板像浮在纸上的墨块，边角用细线"角花"收口。

### 设计红线
1. **场景为王，UI 退后**：场景大图永远是画面的主角，一切面板半透明退后。
2. **少即是贵**：金色与发光效果只给"值得"的东西（突破、机缘、稀有物）。
3. **硬朗边角**：圆角 ≤6px；不用大圆角"气泡感"。
4. **动效要"气口"**：转场、立绘、文字都有呼吸节奏，但单次动效 ≤400ms，不拖操作。

## 二、色板（CSS 令牌，唯一来源）

| 令牌 | 值 | 用途 |
|---|---|---|
| --bg | #0c0a08 | 全局底（墨黑微暖） |
| --paper | rgba(20,17,13,.92) | 面板墨纸底 |
| --ink / --ink-dim / --ink-faint | #d8d2c6 / #9a917f / #6b6354 | 正文/次要/弱化文字 |
| --jade / --jade-bright | #6fae93 / #8fd6b4 | 主交互、生机 |
| --gold / --gold-bright | #c9a96a / #ecd9a8 | 贵重、标题点缀 |
| --cinnabar | #b5483d | 危险、印章、心魔 |
| --wuxing-jin/mu/shui/huo/tu | #d8c690 / #7eb98e / #6f9fc8 / #c96f5f / #c2a36b | 五行体系（战斗灵气/功法/图标） |

品阶色：凡白 → 黄阶 --gold → 玄阶 --shui → 地阶 --huo → 天阶 --cinnabar。

## 三、版式

- 字体：系统衬线栈（Noto Serif SC / Songti / SimSun）；标题加 letter-spacing 0.3–0.5em。
- 标题体系：面板题用小字+金色竖线；篇章/地点题字用大号居中+印章点缀。
- 数字用 tabular-nums，进度条细化（4px），重要条（修为）稍粗。

## 四、界面布局（沉浸式）

桌面：场景图铺满全屏做底（带缓慢 Ken Burns + 暗角），其上浮三组 HUD——
左：角色卷轴（韩立卡/五条/属性/储物袋，可折叠）；
右：叙事卷轴（际遇 + 日志 + 抉择）；
下：在场人物立绘"站"在场景下沿 + 行动栏横排。
顶：一条极简墨带（时间 + 系统按钮）。

手机（≤760px）：场景占顶部 ~38vh 常驻（保持空间感），下方按底部页签切换
剧情（叙事+抉择）/ 行动（际遇+人物+行动）/ 韩立（角色+储物袋）。

## 五、演出语言

- **剧情**：黑场转场 + 地点/章节题字（番剧分集卡）；打字机逐句；立绘淡入位移入场、
  说话者亮、沉默者退后虚化（已有）；关键节点配 CG 大图。
- **战斗**：五行灵气化为五色玉珠池；出招时招式名大字横幅一闪；敌人头顶亮意图；
  伤害飘字按五行着色；突破成功金光 + 钟声。
- **音**：Web Audio 合成的玉磬（点击）、翻纸（推进）、剑鸣（出招）、钝击（受击）、
  古钟（突破）。BGM 留 Audio.playBgm 接口，资源后补。

## 六、图标语言：印章篆字

不用 AI 生成小图标（风格难统一）。功法/法术/物品图标统一为**印章式**：
五行色/品阶色描边的方章，内一个楷/篆单字（如 长・护・凝・剑・毒・针・魂・丹・草・石）。
纯 CSS/内联 SVG 实现，缩放清晰、风格绝对统一、有"道藏"味。

## 六补、考据红线（用户 2026-06-11 钦定，违者返工）

**版本基准（最高优先）：动漫版为唯一情感锚点。** 用户未读小说——剧情、人物、大件、
名场面一律以**动画剧版**为准；小说资料仅用于补动漫未演到的缺口，且补缺内容须标注来源。
动漫与小说冲突处（人物合并/剧情顺序/原创情节/名称差异），**无条件以动漫为准**。
小说专属人物（如黄龙）对用户而言形同原创，可用但不是爽点锚，不得占据高光位。

1. **任何道具/功法/法宝/剧情在设计前，必须先调研动漫版对应剧集**，确认登场篇章与获取方式。
   严守获取时序——例：御风车是**元婴期重返天南、大战穆兰**后所得，与七玄门/黄枫谷/
   乱星海篇毫无关系；神风舟才是筑基期的脚力；风雷翅出自乱星海金雷竹机缘。
2. **任何人物/CG/场景的生成提示词，必须先核对动漫版视觉呈现**（外貌、服饰、神态、
   场景陈设），动漫没给细节的再参考小说描写，不凭印象编造。
3. 拿不准的设定，宁可查证（动画集数/凡人修仙传wiki/原著章节）也不要臆造；
   查证结论沉淀进 docs/lore-*.md，供后续复用。

## 七、美术资产规范（genart）

- 立绘：纯白影棚底生成 → scripts/cutout.js 抠成透明 RGBA（已验证管线）。
- 场景：**必须满幅**——提示词强调"画面铺满整个画幅，无黑边无边框无留白"；
  生成后过 scripts/cropbars.js 自动裁掉残留黑边再入库。
- 风格锚：一律"《凡人修仙传》动画剧版同款，3D 渲染电影质感"，场景横构图。
- 命名：人物 assets/<npcId>.png；场景 assets/<locId>.png；CG assets/cg_<事件>.png。

## 八、节奏与密度（对齐觅长生）

- 每个可云游地点 ≥4 个专属奇遇；负面/两难事件占比 ≥1/3。
- 长闭关必有插曲感（顿悟/走火/幻象/外扰），心魔幻象用故人入梦（张铁/墨大夫）。
- 世界事件流（风云录）按时间推进野狼帮、门派、市井三条线的氛围事件。
- 红线不变：随机只进世界与过程，主线因果手写，韩立不开挂。
