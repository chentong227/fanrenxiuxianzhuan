## 〇、一句话设计论点

**异闻录不是新系统，是一面图鉴。** 它把游戏里早已存在的几套「世界在动」的机制，
按「妖王 / 特殊材料 / 重要情报」三类**收编进一张可翻阅的图鉴**：触发了就留痕，没触发给一定量引导。
所有条目背后都是现成系统在跑（下表），异闻录只新增**一个状态字段 + 一个图鉴页签**。

| 异闻类型 | 复用的现成系统 | 代码落点（现状） |
| --- | --- | --- |
| ①妖王 | `WORLD.beastRumors` + `_maybeBeastRumor`/`_tickBeastRumor` + 探索栖地（PR #29 客观恒在） | `js/world.js` / `js/engine.js` |
| ②特殊材料 | 涟漪限时窗口 `_RIPPLES`（如无主药园）+ 委托 `dynQuests`（如菡云芝烈阳花）+ 大件料 | `js/engine.js` `doRippleWindow` / 1523 烈阳花委托 |
| ③重要情报 | 涟漪链 `_RIPPLES`（流言→确证→窗口）+ 情报面纱 `WORLD.intel`（L0→L2）+ 风云录 `worldNews` | `js/engine.js` 110-199 / `recordIntel` |
| 预知层效果 ①-⑦ | 已在 `docs/lore-大件依赖图.md` §0.2 立档（指路/识弱/召援/悬赏/备战/避坑/借物） | 各映射现成系统 |

> 即：**涟漪（ripple）+ 异闻妖王（beastRumor）+ 情报面纱（intel）是异闻录的三根柱子**，
> 它们都已实装并各有際遇栏渲染（`ui.js renderObjective` 79-199：异闻/风声/线索/请托）。
> 异闻录做的是把它们**汇总成一页图鉴**，并补齐当前剧情范围内的**新条目**。

## 二、异闻录图鉴 · UI 设计

复用现成图鉴框架（`ui.js`：`_compTabs` 页签 + `openCodex` 人物图鉴卡 + `openBigitems` 大件图鉴卡）。
**新增第三个页签「异闻录」**，与「人物图鉴 / 大件图鉴」并列。

```
┌─ 图鉴 ───────────────────────────────────────────────┐
│  [ 人物图鉴 ]   [ 大件图鉴 ]   [ 异闻录 ★ ]            │   ← _compTabs 加一个 tab
├──────────────────────────────────────────────────────┤
│  异闻录　　　　　　　　　　　　　　　已录 6 / 15        │   ← 头部计数（仿大件 gotCount/total）
│                                                        │
│  〔妖王〕                                              │
│  ┌────────────────────────────────────────────┐      │
│  │ 赤目狼王 · 啸月          〔已伏诛〕          │      │   ← 触发并击杀=完整记录
│  │ 彩霞山后山深处。满月之夜啸声尤烈，五行属金。 │      │
│  │ 客观恒在：纵未听闻，深入后山亦可撞见。       │      │
│  │ 异闻所予：①指路 ②识弱（怕雷）④悬赏          │      │
│  └────────────────────────────────────────────┘      │
│  ┌────────────────────────────────────────────┐      │
│  │ 银甲角蟒                〔风声在耳〕         │      │   ← 触发未克=进度态
│  │ 血色禁地浅层。蜕皮成甲，皮甲坚厚。           │      │
│  │ 线索 1/3　踪迹渐明                           │      │
│  └────────────────────────────────────────────┘      │
│  ┌────────────────────────────────────────────┐      │
│  │ ？？？                  〔未闻〕            │      │   ← 未触发=引导剪影
│  │ 引导：身在血色禁地深处，或有巨蟒蜕甲的传闻。 │      │
│  └────────────────────────────────────────────┘      │
│                                                        │
│  〔特殊材料〕  〔重要情报〕  …按类型分区（仿 bigitemCats）│
└──────────────────────────────────────────────────────┘
```

**三种卡态**（仿大件图鉴 `state` 徽章：got/track/unheard）：
- **未闻**（untriggered）：标题打码 `？？？`，只显示 `guide` 一段引导（保证「没触发也有一定量引导」）。
- **风声在耳**（triggered, 进行中）：显示标题 + 线索进度（妖王类 `线索 n/总`，仿際遇栏 phase 文案）。
- **已录 / 已伏诛 / 已得**（completed）：完整显示客观入口 + 异闻所予的 ①-⑦ 效果 + 出处。

## 三、数据 schema 设计

### 3.1 静态定义 `WORLD.yiwen`（新增数组，`js/world.js`）

```js
WORLD.yiwen = [
  {
    id: "beast_chimu",        // 异闻 id（妖王类直接复用 beastRumors id；情报类复用 ripple id；材料类用料/大件 id）
    type: "beast",            // "beast"妖王 | "material"特殊材料 | "intel"重要情报
    title: "赤目狼王 · 啸月",
    node: "caixia", arc: "qixuan",            // 图鉴分区（节点/篇章）
    exist: "彩霞山后山深处盘踞——纵未听闻，深入后山亦可撞见。",   // 客观入口（恒在）
    guide: "身在彩霞山一带，每月或有听闻；深入后山探索可寻踪。",   // 未触发引导
    effects: ["指路", "识弱", "悬赏"],          // 触发后开放的预知层（①-⑦菜单子集）
    link: { kind: "beastRumor", id: "beast_chimu" },  // ★指向既有系统，零新引擎
  },
  // material 例：{ id:"lieyang_hua", type:"material", link:{kind:"quest", id:"hanyunzhi_flower"}, ... }
  // intel 例：  { id:"hunter_lost", type:"intel",    link:{kind:"ripple",  id:"hunter_lost"}, ... }
];
```

`link.kind ∈ {beastRumor, ripple, quest, item, bigitem, story}` —— 异闻录据此**读既有状态**判定卡态，不另存内容。

### 3.2 触发态判定（尽量派生既有状态，最小化新字段）

| type | 「风声在耳」判定 | 「已录/已伏诛/已得」判定 |
| --- | --- | --- |
| beast | `s.beastRumor===id` 或 `s.yiwenSeen` 含 id | `s.slainBeasts.includes(id)` |
| intel(ripple) | `s.ripple?.id===id` 或 `s.rippleWindow?...` | `s.doneRipples.includes(id)` |
| material | 听闻线索/委托接下 | `State.count(itemId)>0` 或 `s.ledger[id]` |

**唯一新增状态字段**：`s.yiwenSeen = []`（曾向玩家浮现过的异闻 id；用于「触发即留痕」的持久化，尤其一次性情报）。
→ `state.js create()` 加 `yiwenSeen: []`；`_migrate()` 加 `if (!d.yiwenSeen) d.yiwenSeen = [];`（铁律：改 schema 同步 _migrate）。
在既有触发点（`_maybeBeastRumor` / `_tickRipples` 起链 / 委托接下 / 料首次入袋）末尾 `pushUnique(s.yiwenSeen, id)`。

## 七、决策点（请用户拍板）

1. **新条目范围**：§1.2 的 N1~N9 全做，还是先做一批（建议先做与已实装链衔接最紧的：N1 银甲角蟒 / N2 寒烟草 / N6 欧阳飞天-情报 / N7 太南地图-情报，其余作引导剪影占位）？

3. **新增状态字段**：认可只加一个 `s.yiwenSeen[]`（其余卡态派生既有状态）这一最小方案吗？
4. **图鉴位置**：认可作为「图鉴」第三页签（人物/大件/异闻录）吗？还是想并入際遇栏/单独入口？
5. **N9 具名妖王**：一时无 ≥2 源具名时，接受「无名妖王·栖地异闻」占位（不凭记忆杜撰），对吗？
