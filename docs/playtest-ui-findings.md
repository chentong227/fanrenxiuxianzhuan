## 战斗体验线（系统维度 · 进行中）
- ✅ **开局空等 6 回合根治（v244）**：实机发现 showdown（药庐子夜夺舍）未传 W → 默认 W=11、
  敌人起手 pos10、move:1 → 玩家被钉 pos1 空点 5~6 次「结束回合」等墨大夫走过来才能首次出手。
  **根因＝密室近战被误配成旷野远距**（非用户「刻意大战场」，是错配）。修：showdown 传 `W:9, enemyPos:5`
  （室内方寸·起手距4，镇魂4格开局即可用）；金光暗算同理传 `enemyPos:5`（贴身突袭叙事）。
  **不违反「不缩刻意大战场」**——旷野战（多敌/boss W=15）不动，只修密室战错配。实机+无头双验证。
- ⬜→✅ **「近/远」气泡标签可读性（已查·现设计已覆盖）**：实机查得敌人头顶标的是**招式意图图标**
  （如「破」=腐骨毒针/刺击），而非笼统「近/远」；出射程才显「近」(逼近意图)。v244 修初始距离后，
  showdown 开局即在攻击意图态，标签语义清晰、不误导。
- ⬜→✅ **射程外前移引导（已查·现设计已覆盖）**：`can-move` 格有**青绿涟漪圈 + 绿墨点 + rippleOut 动画**
  （css `.axis-cell.can-move .dot`/`::before`），脚下召唤点击；敌脚下红椭圆=危险/落点。三套视觉语言
  （意图图标/青移动圈/红危险圈）齐备，可读性基础扎实。
- ⬜ **微优化（低优先·暂不动）**：青移动圈与红危险圈同为椭圆、仅颜色别，新手或混淆——边际收益低，暂留。
- 注：战斗引擎健康——无头自动对战验证可顺利推进到胜负、不死循环；「硬拼必败、靠准备赢」难度成立。

**战斗体验线小结（收尾）**：核心瑕疵=开局空等（v244 已修）。可读性三套视觉语言（意图/移动/危险）经实机查证完备。

### 1. 多敌宽战场·手机端看不全战场（可读性）——✅ 已定方向：导演镜头全景预览
- **现象**：万小山复仇战（W=15，玩家 pos1 vs 双散修 pos13/14），手机视口 V=13 格，
  开局看不全敌人（pos14 的敌人在屏幕外）；前 ~10 回合敌人在画外慢慢接近，玩家够不着也看不见。
- **⚠ 用户裁决（2026-06，重要）**：**大战场是刻意设计，不缩战场、不缩间距**。
  - 前期"敌人慢慢走近、玩家等回合"**本质是为玩家排兵布阵留窗口**（布阵法 / 摆傀儡 / 设伏 / 蓄势）。
  - 只是**前期剧情还没有阵法/傀儡这些系统内容**，所以现在显得"空等"。后续篇章补上这些
    布置手段后，等待回合 = 战略准备期，价值自然显现。
  - **真正要解决的只是"看不全战场"的可读性**——靠**导演镜头/全景预览**（拉远看全局），
    不靠改战场尺寸。
- **方案：战斗内「观阵」全景预览**（保大战场 + 解决看不全）：
  - 战斗操作台加一个「观阵 ◉」按钮（或长按战场空白）：切到**全景态**——
    相机拉到 V=W（容纳所有单位）+ 自动缩放，让整个战场（我方/敌方/阵旗/傀儡/热点）一屏可见。
  - 全景态只供"看清局势 + 落阵/布置点选"，不强制；再点一次（或点单位/格）回到跟随态。
  - 复用现有统一相机（_camParts / cam / zoom），只是把 V 临时设为 W、zoom 取容纳缩放。
  - 落阵/布傀儡的择地（armSpell cell 模式）在全景态下更直观——一眼选远点。
- **注意**：相机是 depth-design.md 精调系统，改前读 §六/§七；新增"全景态"为叠加层，
  不动跟随态默认行为；改后跑 combat.test.js + scale.bal.js。
- **落地见**：`docs/combat-camera-survey-design.md`（导演镜头全景预览设计）。

### 音频/BGM 维度（v248）
- ✅✅ **真 bug：夜景/演出后 BGM 永久卡 16% 低音量不回升**。根因：`bgmEl._vol` 在 duck/unduck/keySfxDuck
  三处被引用，但**全代码从未赋值**→ `unduckBgm` 读 `bgmEl.volume`（此时已被 ducked 压到 ×0.16≈0.042）
  当作"原始音量"恢复 → 越恢复越是压低值。实际体感：每过一段有环境床（夜虫/烛火/风雨）的剧情/夜景，
  音乐就被闷下去再也不回来。修：`bgm()` 创建文件轨 + `startLoopXfade` 循环换实例处都 `el._vol = target`。
  audio.test.js「收床→BGM 恢复」断言由此转绿（不是改测试迁就，是测试本就在抓这个 bug）。
- ✅ **测试套恢复 31/31 全绿**（此前长期 29/31 红，侵蚀门禁可信度）：
  - audio.test.js：BGM 音量基准 0.3→0.26（代码有意降吵闹 BGM_VOL=0.26）、轨道白名单 9→11
    （新增 combat_wild/combat_secret 等）、daily 轨断言改"自管交叉淡化循环（loop=false 但持续播）"。
  - settings.test.js：Node 21+ 内置只读全局 `navigator`（仅 userAgent 无 vibrate），`global.navigator=…`
    赋值不生效 → 改 `Object.defineProperty` 强制覆盖模拟浏览器 vibrate 能力。
- **教训**：长期红测试会让"跑全套"习惯性忽略红项，真 bug（BGM 卡音量）被淹没。深挖第一步＝让测试套全绿可信。

### ⬜ 设计方向决策点：时间窗口互斥（自由度「真取舍」层）
- **现状**：STORY 的 cond 是顺序 flag 链 + 单点倒计时（等待期），**无一处「两个机会重叠、做了A就永久关闭B」**。
  自由度停在「选项顺序」（伪自由），未到「取舍」（真自由）。CONSTITUTION §三明定「自由度=取舍+因果」。
- **为何需用户拍板**：互斥窗口会**永久关闭一条内容**，直接改变玩家的游玩走向——选哪两件既有机会
  互相竞争、收益如何配平，是塑造「这一周目长什么样」的设计方向决策（用户保留亲自体验权的部分）。
- **候选窗口（manifest §四黄枫谷示例 + 现有内容盘点）**：
  ① 离门远行：太南小会备货（买长春功后篇/制符笔）⇆ 青牛镇回乡拜别（小妹出嫁·心境）——同一窗口只够赶一程。
  ② 血色禁地前 3 月：闭关冲修为 ⇆ 坊市备底牌（符箓/丹药）——已是软性时间压力，可升格为硬互斥。
  ③ 黄枫谷各脉差事季：百药园看园（丹道+人情）⇆ 别脉历练（剑道/见闻）——月度互斥。
- **待用户定**：是否实装？先做哪一组？收益配平方向（各有所值、无最优解）？
