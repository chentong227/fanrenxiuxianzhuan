# 箱庭探索 v3 · 三层形态分化（已实装定稿）

> 2026-06-12 经四轮设计讨论定稿。**核心裁决：嵌套箱庭的每一层用不同的玩法形态，
> 形态本身成为"深度的语言"**——走格子（远观舆图）→ 歧路抉择（身在路口）→
> 横版实景（眼前之物），越深越具象越沉浸。
> 状态：**v78 已实装**（L1 舆图 + L3 同轴一体洞窟，血色禁地全程跑通，E2E 全绿）。
> L2 楼阁层待虚天殿篇实装。引擎=js/exploremap.js，渲染=ui.js renderExmap。

## 〇、设计历程沉淀（为什么是这个形态——后续 agent 必读）

四轮讨论淘汰了三个方案，教训都要记住：

| 被淘汰方案 | 死因 |
|---|---|
| 81 格均质网格（v1 现状） | 格子多而画面只有一张，走 40 步眼前世界不变；内容被稀释 |
| 节点间横版行进（暗黑地牢式走廊） | 走廊随机遭遇**撕毁战略承诺**——绕开了威胁节点却在路上被伏击，"用时间换安全"成笑话；目的是见人/交易时，双层移动纯属烦恼 |
| 处境六件套（地形语法/处境栏/步履卡/暴露度…） | 堆系统做加法。复杂度与体验非线性相关 |
| 行程规划制（80 Days 式纯选路线） | 过于抽象，失去"我在移动"的演出感与空间感 |

**用户的真实诉求**（不变量）：
1. 韩立式"**用时间换安全**"的决策（绕路/等待/备符——稳字诀），不是爱玩走格子本身；
2. **每次移动都有演出**，格子总数要少（每个都是地标）；
3. 采集与战斗**自然过渡**（场景不切，敌人入画即对阵轴）；
4. **剧情做成具体的操作动画**——演出即玩法（观战/隐蔽/伺机）。

## 一、三层结构总览

```
L1 野外舆图层（走格子·战略）          ←—— 血色禁地全图 / 虚天殿外殿
   水墨舆图 + 9~12 个地标节点 + 连线
   灾厄钟 / 巡逻威胁（杀气阴影）/ 移动演出
   遭遇野外敌人（封岳式）→ 直接对阵轴开打
        │ 走进山洞 / 上楼（压栈）
L2 歧路层（路径抉择·轻量）            ←—— 虚天殿宝光阁楼层（左右路）
   复用剧情卡 UI：左路/右路/楼层选择
   每个岔口 = 一次有信息的抉择（神识/情报提示两侧动静）
        │ 推开最深处的门（压栈）
L3 横版深窟层（演出+终局·沉浸)       ←—— 墨蛟山洞 / 虚天殿内殿
   横版实景，段落制推进，入层前"洞口印记"存档提示
   观战演出 / 隐蔽采集 / 不可避免的 boss 战
```

- **层数按需**：血色禁地=L1+L3（野外秘境无楼层）；虚天殿=L1+L2+L3 完全体。
  不为了三层而三层。
- 引擎=ExploreStack 状态栈：进层压栈、出层弹栈回父层原节点。

## 二、L1 野外舆图层（战略：用时间换安全）

- **地标节点 9~12 个**（比 v2 蓝图再砍）：药圃、深潭洞口、集市、猎场、庇护岩穴……
  每个有名字、有内容，没有空格子。
- **移动演出**：棋子沿线走 1~2 秒（雾散开、一行路途见闻、环境音）——可跳过，
  复访加速。路上**永不强制战斗**（战略承诺完整）。
- **灾厄钟**：每次移动/驻守耗钟。五日大限、菡云芝第三日到、钟吾某日摆摊、
  血幕逐日收缩（外环节点关闭）——时间涨价，玩家自己算出"何时该冒险"。
- **巡逻威胁**：封岳是图上会动的棋子，巡逻路线=情报（L2 侦察可见杀气阴影）。
  踩进他所在节点/被他堵住 → 警兆 → **直接对阵轴**（野外遭遇不进 L3）。
  主动狙杀=读他的路线，反向埋伏。
- **驻守**：原地等 X 钟（等人/打坐恢复/警戒），一个按钮不是系统。
- **到达即所得**：见人→立绘对话直接弹出；采集→单屏场景+热点层（神识显形）；
  入口→压栈。节点内零二次移动。

## 二·补、迷雾层（后山猎王篇·P3 定稿 2026-06-18）

> 旧 explore.js 的 81 格网格野图退役，迁入节点图引擎。野外秘境（非据点、非剧情副本）
> 由此长出**战争迷雾**：不再是"全图地标一眼看全"，而是雾里摸索、循迹寻王。
> 三层定稿——**客观/迷雾/传闻三层各司其职，信息 ≠ 现实**。引擎以 `map.fog:true` 选启，
> 不动血色禁地（xueshi_l1 无雾照旧，零回归）。

### ① 客观层（红线·不可动）
节点、妖兽、机缘、赤目狼王巢 **客观存在**、可探可战——世界不因你看不见而消失，也不因
你没听过传闻而凭空生出。揭雾只改变"你看见多少"，绝不改变"世界有什么"。

### ② 迷雾层（张力·可见性——节点四态）
入图整片覆雾。每个节点处于四态之一（`ExploreMap.fogState(x, id)`）：

| 态 | 名 | 玩家可见 | 可达 | 语义 |
|---|---|---|---|---|
| `unknown` | 未知 | 笼在雾里·不可见 | 否 | 雾团，连轮廓都没有 |
| `glimpsed` | 窥见 | 雾影·见轮廓不知其详 | 是（相邻） | 站在已至点旁瞥见的下一批 |
| `rumored` | 风闻 | 标出·知其所在 | 是（可盲走直往） | 传闻预亮，纵未亲临也知道在哪 |
| `visited` | 已至 | 全显 | — | 亲历，名实俱全 |

**三种揭法（异质·有策略·诚实）：**
1. **邻接点亮**：走到一个节点 → 与它相邻的节点升为"窥见"（雾影里浮出轮廓）。
2. **瞭望高地**（`node.lookout`）：登高一处 → 揭开一大片（`reveals` 列表或全图"窥见"）——
   "上哪座高地"成为战略选择，登高揭得多但绕远耗时。
3. **远距感知梯度**（`node.sense` / `map.senseSources`）：极深兽吼、血腥气——感知到危险的
   **方位与强弱**，但**不给精确坐标**。零传闻也能循声朝狼王巢的大致方向摸过去（梯度越强
   越近）。诚实预告，不是精确雷达。

### ③ 传闻层（仅降雾·绝不增删世界）
- 传闻**只做一件事：降低雾重**——把若干节点预亮为"风闻"（`ExploreMap.applyRumors`）。
  它**从不创造、从不删除**任何世界内容（信息 ≠ 现实）。
- 传闻 = **情报红利**：知狼王巢的路径 / 巡逻路线 / 弱点 → 入战"有备而来"
  （伏击先手 / 伤害减免，落到既有 `intel` 钩子）。
- **无传闻照样能探能战**——只是雾重摸黑硬碰，没有先手红利。传闻是"信息经济"，不是通关钥匙。

### 为什么胜过旧 81 格
旧版：81 格均质 + radius 揭格——走 40 步眼前世界不变，内容被稀释成"扫雷"。
新版：**地标异质**（每次揭雾 = 一个有名有姓的具名地标）+ **瞭望的战略选择** +
**危险梯度的诚实** + **传闻作为信息经济**。揭雾从"清扫"变成"读山"。

## 三、L2 楼阁层（与 L1 同引擎的"室内语法"——2026-06-12 用户裁决修订）

> 用户洞察：节点图实装后发现 L1 与想象中的 L2 本是一物。**裁决：同一个节点图引擎
> 承载 L1/L2 两层，靠图语法（kind 配置）差异化**，不另做系统。

| | L1 野外图 kind:"field" | L2 楼阁图 kind:"floor" |
|---|---|---|
| 拓扑 | 开放网（自由绕路回头） | **递进结构**（前厅→侧殿→阁楼，节点竖排=楼层断面） |
| 威胁 | 会动的巡逻者 | **静而隐蔽**：陷阱房/假宝/禁制反噬（神识侦察价值放大） |
| 时间 | 灾厄钟 | 同一口钟（子图烧栈底的钟，引擎已支持），禁制另耗灵力 |
| 核心决策 | 绕不绕、何时冒险 | **进哪扇门、取哪个宝** |

L2 独有三件（"探索+选择"的本体）：
1. **不可回头点**：禁制门过了就合拢——这一步不可撤销，进深即赌注；
2. **锁与钥匙**：禁制要解法（神识解谜/阵法知识/钥匙道具）——资源花在哪扇门上；
3. **宝向取舍**（宝光阁精髓）：每层多向宝物**取其一则余者封闭**——机会成本明面化。

UI 复用 L1 舆图渲染，节点竖排成楼层断面（往上点=上楼）。

## 四、L3 同轴一体洞窟层（已实装定稿 v78——探索与战斗是同一条轴）

> **2026-06-12 用户裁决迭代**：L3 不是"横版走廊+进战斗切场景"，而是**探索轴与对
> 阵轴物理同构**（同一条 27 格轴、同一张长卷背景、同一批站位）。开战瞬间天地不换、
> 人不挪窝——只是规则从"走格采集"切到"回合制"。

**入层仪式**：进洞前提示+自动快照（"洞口印记"，败退/逃跑回洞口重来，单档体系不变）。

### 同轴一体五机制（全部实装，test/exploremap.test.js + journey.test.js 覆盖）

| 机制 | 规则 | 实现 |
|---|---|---|
| **出手即开战** | 探索态手牌常驻（攻击法术全亮在面板上）；**目标入射程的那一刻按钮才点得动**，按下=该法术作为开局第一击+宣战。无独立"偷袭按钮"。 | `Engine.cavePlayerSpells()` 滤出可开战法术；`exmapCaveStrike(spellId)` 先 `exmapCaveFight()` 再 `cast(spellId, 0)` |
| **惊动度（expose）** | 采集/布置/贴近妖兽都涨惊动；满 50 它有备（失先机+开局面向你）；未满=偷袭成功，**它定身一拍白送**（定身目标闪避归零——首击必中，定身符同理） | `nearExpose` 距离带 + `caveFightInfo().sneak`；combat.js dodge=0 on dingshen |
| **感官梯度** | 走近时先闻其声（远斗绫帛破空/妖吼，弹幕字幕+合成音效），再见远辉（出画目标在画框边缘起辉光脉动+名牌） | `soundCues` 距离阈值事件；`cave-far-glow` 元素 |
| **战中采集** | 开战后热点不消失——邻格热点可花**一个主行动**摘下（跑着打着顺手薅灵草，贪与稳的回合制等价物） | `Combat.playerTake(hotId)` / `playerCanTake` |
| **预置先手** | 开战前在轴上布阵旗（困足/聚灵）、埋符（伏火）、埋傀儡（铁奴）——开战时原样生效 | `preps[]` → `_applyCavePreps` 转 zones/mines |

### 镜头与纵深语法（v78 定稿——"战场的大才是气势"）

- **死区镜头**：人在画面里走、镜头只在贴近画框（边缘 3.2 格）时才拉——"是人滑过
  画面，不是世界从脚下滑走"。战斗态额外尽量把锁定目标拉进画框（打谁看谁），与
  玩家死区冲突时玩家优先。
- **三层视差**：长卷 pano 背景（半速退行）→ 轴面（人物/格子，全速）→ **前景暗带
  fg-band**（纯 CSS 岩影草影剪影，随世界层掠过脚前）——远中近三速，纵深钉死。
- **立绘缩档**：战斗全身立绘缩一档（≈21vh，竖屏 17vh）——人物小了，洞窟才高、
  战场才远；多单位同框不挤。
- **错落站位**：非玩家单位奇数格整体退后半步（上移+微缩+微暗）——一条轴读出
  "路有宽度"；玩家恒站前排不晃。
- **朝向即叙事**：所有单位动态面向当前对手（素材自带朝向元数据 `Art.battlerFace`，
  缠斗双方互盯、被惊动后妖兽转头锁你）。

- 一个篇章只配 1~2 个 L3（boss 级才开洞）。

## 六、关键新基建：演出脚本系统（cutscene DSL）

> **2026-06-14 升级**：用户裁决待定 B——优先级极高、大力做、越好看越好、成本可忽略。
> 已抽出为独立正式档 **docs/cutscene-design.md**（数据驱动演出管线 + 交互演出 beat + 据点抵达打样）。
> 本节保留为索引；细节以 cutscene-design.md 为准。

用户裁决"演出和把剧情做成具体操作动画极其重要"——这是本次重做的真正投资：

- **数据驱动的演出段**：原语=镜头平移/角色入画退场/台词气泡/特效/音效/等待点击/**交互 beat**。
  剧情节点与 L3 段落都用它描述，不写一次性代码。**向后兼容现行剧情卡 `text:[]`**。
- **随时可跳**（点击快进到段尾），复访零负担。
- 一次投资全篇章复用：以后每个名场面（观战/伏击/重逢/突破异象）都吃这条管线。
- **打样目标**：嘉元城据点（抵达演出+节点图+一段交互 beat），解决"嘉元城和七玄门没区别"。

## 七、设计难点与对策（评审记录）

| 难点 | 对策 |
|---|---|
| 演出管线工程量 | 原语收敛到 6 种以内，数据驱动；先做墨蛟洞一例打样 |
| L3 手工成本 | 段落模板填空+美术 2~3 张拼接；每篇章限 1~2 个 |
