# 游戏设计宪法（CONSTITUTION）

> 2026-06-29 立。本文件是**全项目设计的最高权威**，凌驾于 `docs/` 下所有其他文档之上。
>
> **它不规定内容，只规定约束。** 任何篇章怎么填、数值具体多少、剧情怎么写——
> 那是「细则」（其余 docs）和「代码 + 测试门禁」的事。宪法只回答一个问题：
> **「任何新东西落地之前，必须满足哪些不可违背的铁律？」**
>
> 设计目标：本文件必须**短到能背下来**。背不下来的宪法不是宪法，是又一份会漂移的胖文档。

---

## 〇、效力声明（治理——解决「70+ 文档无优先级」的元问题）

1. **本文件 = 宪法**：定铁律与冲突裁决权。
2. **其余 `docs/*.md` = 细则**：管「某一篇/某一系统怎么填」。细则服从宪法。
3. **代码 + `test/*.js` = 执法**：宪法的可机器校验部分由测试门禁强制（见 audit-gate.md）。
4. **冲突裁决**：任意两份文档冲突时——
   - 与本宪法冲突 → **以宪法为准**，细则即刻修订。
   - 细则之间冲突 → 以**新日期**为准，且必须在两份都留「已被 X 取代」批注（杜绝再现「燕家堡 vs 黄枫谷代工地点」式悬案）。
5. **唯一权威源原则**：任何一个事实（剧情/数值/考据）只能有一个权威出处。
   其余引用它，不复制它。复制即埋下漂移。

## 一、第一性原理（七条铁律 · 立项即审）

> 任何新节点 / 新法宝 / 新功法 / 新敌人 / 新系统，提交前逐条自查。
> 违反任意一条 = 不准实装。

### 铁律 1 · 骨架忠于动漫，血肉归玩家
- **骨架（主线锚）**：韩立必经之事（筑基、燕家堡、落海星海……）忠于动漫官方篇章序，短、硬、不可错过。考据红线（≥2 源互证）在此适用。
- **血肉（自由帆）**：抵达每个锚之前「怎么准备、与谁结缘、花掉什么、欠下什么」——**这是 90% 的游戏时间，归玩家**。
- **判定**：拿不准一段内容是锚还是帆，用 pacing-design §一「三问」。**默认是帆**；只有动漫点名顺序、错过伤害叙事的，才升格为锚。

### 铁律 2 · 回合 = 月，时间是唯一全局货币
- 任何行动**必须消耗月**（驻足读告示等零成本微动作除外，且必须显式标注为「不耗月」）。
- 任何收益**必须能被时间换算**——「这值不值得花一个月」必须是玩家能算的账。
- **禁止**做出「不花时间就能白嫖」的正反馈循环（违反则是刷子，节拍器失效）。

### 铁律 3 · 选择必须闭环（因果不许只记不结）
> 直接针对漂移 #1。这是「好玩」与「自由度」的共同技术根。
- 任何 `writeLedger(id)` / 设关键 flag 的选择，**立项时必须同时声明它的「兑现窗口」**：在哪个未来节点、以什么形式（演出/难度/资源/命途）兑现，且兑现时 `settleLedger` **点名出处**。
- **找不到兑现窗口的因，不准种**——要么降级为纯 flavor（不写 ledger，只给当场文字），要么补上兑现节点再实装。
- 例外：成就型留痕（年表里程碑）可只记不结，但**不得占用 ledger 命名空间**，走 `addMilestone`。

### 铁律 4 · 数值一律吃尺子，禁裸加平铺
> 继承 A2 承重墙（balance-master-design.md），升格为宪法级。
- 一切伤害/血量/加成走 `balance.js` 纯函数，读时计算，**存档 schema 不变**。
- **严禁裸 `+N` 平铺加成**——附魔/丹药/buff 一律乘性或随境界缩放（高境界必归零的平铺是 bug）。
- 法宝立项必标可驱境界门槛（`driveRealm`）；消耗性底牌（`chargeCost`）豁免越阶折扣。
- **未决期临时口径**（针对漂移 #5，redesign-master 分级制拍板前）：新法宝/招式**暂按现行 balance.js 既有公式 + driveRealm 标注**定值，且**在该条数据旁留 `// TODO:tier 待 redesign-master 拍板后改吃 tier 制`**。不许再「拍一个孤立大 base 模拟好招」。

### 铁律 5 · 乘法优先，立新系统须四问
> 继承 multiply-design 三律。
- 新玩法先问「旧系统相乘可得否」。能乘则乘。
- 立新系统必须过大件四问（想要 / 准备苦 / 过程险 / 到手蜕变）并在 roadmap 留案。
- **零教学**：机制必须挂在修仙常识上（五行生克/寒热毒理/灵气环境），需要弹教学窗才能懂 = 重做。

### 铁律 6 · 三层惦记任何时刻不为空
> 继承 multiply-design 节拍器三规。
- **远**（月级·前路剪影）/ **中**（周级·涟漪/异闻/轴进度）/ **近**（分钟级·本月产出/下一格）三层任意时刻皆非空。
- 进一步（针对漂移预埋观察 #2）：**近反馈应尽量喂养某个中/远惦记**，而非孤立结算。采药不只是 +1 药理，应是「向某个目标推进一步」。

### 铁律 7 · 败有所得 · 一致感
- 战斗/抉择失败不卡死、不删档：给信息 / 给资源 / 给更难更香的补救径（爽文契约 fail-forward）。
- 剧情强 = 数值强；背景强者三态（传说/在场/际遇），**永不进风云榜赛道**，永不归玩家管。

## 二、存档与工程不可破红线（继承 AGENTS.md §四，宪法级重申）

- **存档 schema 只增不改**，新字段走 `_migrate` 惰性初始化。改 state 必同步 `_migrate`。
- **改战斗/数值必跑** `node test/scale.bal.js` + 相关 `.bal.js`，不全绿不许 push。
- **写含中文的文件禁用 PowerShell Set-Content/Out-File**（编码事故红线），走专用编辑工具或 node 脚本。
- 发版走 `node scripts/bump.js`。
- 移动端基准：iPhone 14 Pro Max（430×932, DPR3）。

## 三、宪法与「好玩 / 自由度」的关系（立宪意图备忘）

本宪法的设计意图，是让「自由度」与「好玩」有结构性保障，而非靠堆内容：

- **自由度 = 取舍 + 因果**：铁律 2（时间唯一货币）制造稀缺，铁律 3（选择闭环）让稀缺中的每个选择都长出后果。二者合起来 = open-world-replayability 文档所说的「编织」。
- **好玩 = 选择有重量**：铁律 3 + 铁律 6 进阶项，直接对治漂移盘点的「做啥都不重要」病症。
- 故：**凡是削弱「选择重量」的内容，即便单看很精致，也违宪。**

## 四、修宪程序

- 宪法条款的增删改 = 重大决定，须用户明确拍板，并在本文件顶部记录日期与缘由。
- 细则（其余 docs）可自由演进，但不得与现行宪法冲突；发现冲突即修细则，不修宪法（除非走修宪程序）。
