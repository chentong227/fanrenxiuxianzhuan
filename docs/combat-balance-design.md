# 战斗平衡系统（独立设计立项 · 骨架）

> 用户裁决（2026-06-11）：战斗平衡不打补丁——**整个战斗系统是承重墙、build、爽与真实的
> 精髓交汇处，必须独立设计**。本档先立骨架与问题清单，完整设计在专门周期与用户对谈定稿。
> 法源：power-design.md（乘区/加区/特区/越级公式/操作浮动盘）、retention-design.md（爽文契约）。

## 一、已知问题清单（设计输入，暂不修）

1. **无脑方案**（用户实测 + 代码核实）：基础敌人全部只有单一攻击（normal 平A，atk 9~14），
   而长春护体盾值 14 ≥ 一切平A → 「每回合护体+眨眼剑法」零思考必胜循环。
   根因：敌人无意图多样性（pierce/charge 只在 boss 身上），护体无对策牌。
2. 战斗内决策密度不足：灵气分配的"组合爽"没起来（招式池小、敌人不逼你换解法）。
3. 数值无总表：敌我成长各自拍脑袋，无统一锚点（境界乘区表未落实到 balance.js）。
4. 操作不被奖励：看破意图后的正确应对无显式收益（操作浮动盘未实现）。

## 二、设计原则（已定，来自既有宪法）

- 战力 = 境界乘区 × build加区(1.0~2.0) + 特区；公式给**赔率**，操作定胜负。
- 爽文契约：难是叙事的皮——敌人"看起来凶"，解法永远提前递到玩家手里；fail-forward。
- 每个敌人 = 一道"解谜题"：至少 2~3 种攻击意图，存在最优解法（读招应招），
  也存在暴力解法（build 压制）——巧赢和碾赢都成立，但巧赢有额外奖励（漂亮的赢勋章）。
- 韩立四灵根缺土、总量低是身份认同：正面亏，靠毒/暗器/剑/算计翻盘。
- 突破复用战斗引擎（觅长生同款思路），平衡表一套两用。

## 三、待设计议题（专门周期与用户对谈）

1. 境界乘区数值锚点表（练气1~7层敌我基准：HP/攻/灵气总量/神识/闪避）。
2. 敌人意图语言：normal/pierce/charge/release 之外是否加 guard（格挡姿态）/
   summon（唤援）/poison（敌方叠毒）等；每类敌人的意图脚本（狼=兽性突进型，
   修士=法术节奏型，傀儡=蓄力重击型……）。
3. 护体/回血的对策化：盾上限、衰减、破甲频率——让防御是"选择"而非"默认"。
4. 灵气经济：结转上限、凝神收益、灵气总量随境界的成长曲线。
5. 招式池扩容节奏与流派成型（毒师/暗器/稳健三流派的招式-敌人克制矩阵）。
6. 蒙特卡洛验收标准：showdown.bal 式的胜率梯度（备牌多寡→胜率），各境界各流派全覆盖。
7. 操作浮动盘实现：读招正确应对的显式奖励窗口、底牌时机倍增、战后复盘归因。
