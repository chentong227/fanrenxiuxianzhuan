# 战斗平衡系统（独立设计立项 · 骨架）

> 用户裁决（2026-06-11）：战斗平衡不打补丁——**整个战斗系统是承重墙、build、爽与真实的
> 精髓交汇处，必须独立设计**。本档先立骨架与问题清单，完整设计在专门周期与用户对谈定稿。
> 法源：power-design.md（乘区/加区/特区/越级公式/操作浮动盘）、retention-design.md（爽文契约）。

## 一、已知问题清单（设计输入，暂不修）

1. **无脑方案**（用户实测 + 代码核实）：基础敌人全部只有单一攻击（normal 平A，atk 9~14），
   而长春护体盾值 14 ≥ 一切平A → 「每回合护体+眨眼剑法」零思考必胜循环。
   根因：敌人无意图多样性（pierce/charge 只在 boss 身上），护体无对策牌。
2. 战斗内决策密度不足：灵气分配的"组合爽"没起来（招式池小、敌人不逼你换解法）。
3. 数值无总表：敌我成长各自拍脑袋，无统一锚点（境界乘区表未落实到 balance.js）。
4. 操作不被奖励：看破意图后的正确应对无显式收益（操作浮动盘未实现）。

## 二、设计原则（已定，来自既有宪法）

- 战力 = 境界乘区 × build加区(1.0~2.0) + 特区；公式给**赔率**，操作定胜负。
- 爽文契约：难是叙事的皮——敌人"看起来凶"，解法永远提前递到玩家手里；fail-forward。
- 每个敌人 = 一道"解谜题"：至少 2~3 种攻击意图，存在最优解法（读招应招），
  也存在暴力解法（build 压制）——巧赢和碾赢都成立，但巧赢有额外奖励（漂亮的赢勋章）。
- 韩立四灵根缺土、总量低是身份认同：正面亏，靠毒/暗器/剑/算计翻盘。
- 突破复用战斗引擎（觅长生同款思路），平衡表一套两用。

## 二补、用户验收七条（2026-06-11 晨，v30 实测反馈 = 周期二需求定稿）

1. **行动/见闻分屏割裂**：点了行动不知道发生了什么 → 行动页要有即时反馈条（最新见闻摘要）。
2. **灵气过多**：灵气总量必须随境界与功法层次成长（原著：韩立靠灵气底蕴+万年灵乳补灵力
   才险胜温天仁——灵气总量是核心战斗资源，须挂境界乘区）。
3. **技能过多混乱**：第一章就一排按钮，后篇必翻页 → 出战技能装配化收紧（如5槽）；
   **暗器/毒=底牌独立系统**（不占技能位），为后续武器/防具留架构。
4. **连环眨眼不够上位**：纯气换伤害无质变感 → **替换**眨眼连击（进化而非并列），
   强化为多段连击（行动经济特区：一剑化数剑）。
5. **余子童莫名死亡**：BUG——元神(soulOnly)被毒发直接掉血（毒tick未走takeDamage），
   毒草毒死元神荒谬，修。
6. **双击缩放锁死UI**：touch-action/viewport 修复。
7. **自由度定位**：主线≠达摩克利斯之剑，= 试金石+必经路；**最有挑战的内容应分布在
   主线之外**（秘境深层/隐藏强敌/高风险奇遇）——自由经营要有天花板内容可挑战。
8. **总指令**：战斗系统重构时，功法与灵技系统一并重构清楚
   （分类：功法=修炼法授灵技 / 灵技=法术 / 武技=凡人武学 / 底牌=消耗手段 / 后续:武器防具）。

## 二补·二、灵气经济三件套定稿（2026-06-11，v34 实装）

> 教训（用户两轮实测）：v31 砍产出未动成本 → "没有战斗手段"；纯 stash 凝神 → "凝神也不加气"。
> **产出、成本、调度必须一体设计**，并由 encounter.bal.js 双指标蒙特卡洛把守。

1. **产出**：总量 = 底蕴4 + 练气层数（5→11），不变。
2. **成本定价原则**：基础招 1~2（练气一层每回合必有 1~2 手段——永远打得出）；
   爆发招 3+；底牌 1。现值：眨眼金1 / 吐纳木2回6 / 护体木2盾10 / 连击金3 /
   连环金3 / 镇魂木1水1（决战第三波必须打得出）/ 毒·针金1。
3. **调度（凝神静气）**：以1木换1点随机灵气（按灵根权重——缺金赌金的换币器，期望净0
   不产气）+ 蓄势（本回合余气结转至境界上限）。oncePerRound。
4. **防御衰减**：护体每回合消散一半（盾是应招不是存款；法宝护体 _fixedShield 例外）；
   战中回血弱（吐纳6）——"续航受限，胜负在攻"。
5. **锚点双指标**（杂鱼战胜率高+损耗真实；挑战战胜率区间）：
   一层vs灵狼 100%胜/60%末血（赢但掉肉）；三层vs散修 93%/46%（吃力）；
   四层vs虎王 83%（挑战）；碾旧区 91%+末血（无损可感）；胜率/损耗随境界单调。

## 三、待设计议题（专门周期与用户对谈）

1. 境界乘区数值锚点表（练气1~7层敌我基准：HP/攻/灵气总量/神识/闪避）。
2. 敌人意图语言：normal/pierce/charge/release 之外是否加 guard（格挡姿态）/
   summon（唤援）/poison（敌方叠毒）等；每类敌人的意图脚本（狼=兽性突进型，
   修士=法术节奏型，傀儡=蓄力重击型……）。
3. 护体/回血的对策化：盾上限、衰减、破甲频率——让防御是"选择"而非"默认"。
4. 灵气经济（2026-06-11 与用户定稿）：**小境界加数量，大境界改规则**。
   - 练气：总量=底蕴4+层数（5→11），纯数量学习曲线（v31 已实装）。
   - 筑基：基数跳 ~15、小境±2；新规则=**蓄势解禁**（结转上限大涨，跨回合攒大招）
     +**液化转换**（每回合2杂灵气→1指定灵气，松动四灵根死限）。
   - 结丹：基数~20；新规则=**金丹自供给**（开局自带本命灵气+每回合额外产出；
     **金丹品阶由筑基/结丹过程表现决定**——突破表现跨篇章复利，"完美筑基"执念同款）。
   - 元婴：基数~24；新规则=**第二行动体**（元婴独立小池每回合一个低耗法术；
     出窍=终极底牌）。
   - 化神：基数~28；新规则=**领域**（开场改写战场规则；化神老怪先用它打玩家——
     背景强者生存战的机制核）。
   - 原则：不加新系统，同一套五行灵气的规则分层；数字不爆炸，乘的是规则；
     每个大境界突破收益清单头条=新规则（质变=新动词）。引擎均在 combat.js 骨架内扩展。
5. 招式池扩容节奏与流派成型（毒师/暗器/稳健三流派的招式-敌人克制矩阵）。
6. 蒙特卡洛验收标准：showdown.bal 式的胜率梯度（备牌多寡→胜率），各境界各流派全覆盖。
7. 操作浮动盘实现：读招正确应对的显式奖励窗口、底牌时机倍增、战后复盘归因。
