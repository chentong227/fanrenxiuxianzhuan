# 演出脚本系统（Cutscene DSL）· 头号地基

> 2026-06-14 用户裁决（待定 B）：**优先级极高，大力做，越好看越好，token/时间成本可忽略。**
> 这是本周期的主投资——"把剧情做成具体的操作动画"（用户原话，explore-redesign §六 早已立项，
> 当时被简化成"弹幕字幕+镜头语法"，未做独立 DSL）。本档把它升级为正式的**数据驱动演出管线**。
>
> 红线：①复用现有底座（FX 粒子引擎 / audio bgm / Art 立绘朝向 / 箱庭 L3 镜头语法），**绝不另起炉灶**；
> ②动漫版为唯一剧情锚点（演出内容考据红线照旧）；③零教学（机制挂修仙常识）；
> ④**单屏铁律**：手机竖屏一屏放下，演出永不要求竖向滚动；⑤**随时可跳**（点击快进段尾，复访零负担）。

---

## 一、为什么要做（问题与目标）

### 现状（已读代码核定）
剧情卡=一段**线性台词流**：`story.js` 每个 stage 的 `text:[]` 数组，元素是
- 纯字符串 = 旁白叙述
- `{ scene: "地点·时间" }` = 场景标题卡
- `{ aside: "…" }` = 韩立心声
- `{ say:"角色", tone/emo, text:"…" }` = 角色台词

stage 级还有 `cg`(背景图) / `bgm`(音乐 cue，如 "tense") / `title` / `objHint` / `onArrive(s)`(给物/置 flag/年表/名声) / `choices`。
渲染在 `ui.js`（剧情卡逐条点击推进）。**这套读起来够味，但"看"是静的**——没有镜头、没有立绘入退场、没有定位特效，名场面全靠文字脑补。

### 目标
一条**数据驱动的演出管线**，让每个名场面（投信/夺丹/重逢/突破异象/观战/伏击）都能写成
**镜头+立绘+特效+音效+台词+交互**的"分镜脚本"，而不写一次性代码。一次投资，全篇章复用：
- 剧情卡 `text:[]` **向后兼容**（旧字符串/scene/aside/say 全部照旧能跑）；
- 在同一数组里**新增演出原语**，作者按需加镜头/立绘/特效；
- 高潮处把**玩法塞进演出**（观战时的"伺机出手"、隐蔽时的"屏息"、抉择 QTE）——演出即操作。

## 二、原语集（收敛到 ~8 种，多了就是另一个系统）

> explore-redesign §六 立的铁律：原语 ≤ 6~8 种、数据驱动、可跳。下表每条都映射到**已存在的底座**。

| 原语 | 形态 | 落地底座（复用） |
|------|------|------------------|
| **台词/旁白/心声** | `"…"` / `{aside}` / `{say,emo,tone}` | 现行剧情卡渲染（ui.js）——零改动兼容 |
| **`scene`** | 场景/时间标题卡（可带背景图淡入） | 现行 `{scene}` + `cg` 背景；升级为可指定 `bg`/`transition` |
| **`cam`（镜头）** | `pan`/`zoom`/`focus`/`shake`/`hold` | 箱庭 L3 已有**死区镜头 + 三层视差 + 锁定目标入画**；抽出复用 |
| **`actor`（立绘）** | `enter`/`exit`/`move`/`emote`/`face` | `Art` 立绘 + `battlerFace`(l/r/c 朝向元数据，红线：入库目检) |
| **`fx`（特效）** | 在锚点放粒子/闪光/震屏/剑环/雷击 | `FX` 引擎现成：flash/shake/burst/lightning/ribbon/swordRing/trail/material |
| **`sfx`/`bgm`（声）** | 音效一击 / 配乐切换淡入淡出 | `audio` 模块（现行 stage `bgm` 字段升级为可在段中切换） |
| **`wait`（节拍）** | 等点击 / 定时 / 等演出结束 | 推进器：默认等点击，可设 `auto:ms`（可跳） |
| **`beat`（交互演出）** | 把一个操作嵌进演出（见四） | 复用箱庭"出手即开战"/抉择卡/聚灵珠引擎 |

**作者书写示例（向后兼容 + 新原语混写）**：
```js
text: [
  { scene: "嘉元城 · 墨府门前", bg: "cg_mofu", transition: "fade" },
  { cam: "pan", to: "gate", ms: 1200 },                 // 镜头扫过朱门
  "三个月风尘，嘉元城到了。",                              // 旧式旁白，照旧
  { actor: "mocaihuan", enter: "left", emote: "scheme" },// 立绘从左入场
  { say: "墨彩环", emo: "scheme", text: "你就是…那个土里土气的黑小子？" },
  { fx: "mote", at: "mocaihuan", o: { color: "#cfe" } }, // 调皮的灵气微尘
  { aside: "……墨大夫信里到底写了什么。" },
  { cam: "shake", px: 6 }, { sfx: "thud" },              // 强调一击
]
```
> **设计纪律**：原语**全部可选**——一句普通旁白依旧只写字符串。演出是"加料"，不是"必填表格"。
> 镜头/特效缺省时回退到现行静态卡（fail-soft），低端机/降级模式（FX `_degraded`）自动减粒子。

## 三、镜头与立绘语法（直接搬箱庭 L3 的成熟件）

explore-redesign §四 已沉淀一套"战场的大才是气势"的镜头语法，**演出系统直接复用**：
- **死区镜头**：人物在画面里走，镜头只在贴近画框边缘时才平移——"是人滑过画面，不是世界从脚下滑走"。
- **锁定入画**：演出可 `cam:focus` 把某角色/某物拉进画框（"看谁说谁"）。
- **三层视差**：长卷背景半速退行 → 中景人物全速 → 前景暗带（fg-band）掠过——纵深钉死。
- **立绘缩档**：演出立绘缩一档（≈21vh / 竖屏 17vh），多人同框不挤；据点演出可再调。
- **朝向即叙事**：`actor.face`/`battlerFace`（l/r/c，c=正面永不镜像）；红线——**新立绘入库必目检实际朝向**
  （箱庭篇曾 11/16 张登记错）。`actor:move`/`enter` 自动按目标位定朝向。

立绘**情绪档**（emo）对接现有 say 的 emo 字段（scheme/sad/cold…），演出里可单独 `actor:emote` 切换表情
（美术按需出多表情切图；缺省用中性档，fail-soft）。

## 四、交互演出（`beat`）——"剧情做成操作动画"的核心

> 这是用户最看重的一点。静态分镜只是"好看"；**把操作嵌进高潮**才是"代入"。
> 全部**复用已有玩法引擎**，不发明新战斗：

| beat 类型 | 玩法 | 复用 |
|-----------|------|------|
| **观战（spectate）** | 韩立藏拙旁观大修混战，玩家只能"看/趁乱行事/择机插手" | 箱庭 L3 观战段（墨蛟洞·南宫婉缠斗已是范本） |
| **伺机出手（strike-window）** | 演出推进到某拍，攻击按钮短暂可点=偷袭首击（错过=正常开战） | 箱庭"出手即开战"+惊动度（expose）机制 |
| **屏息/隐蔽（hold-breath）** | 巡逻者经过，玩家点住"屏息"度过危险拍（松手=暴露） | 箱庭暴露值一根条；fail-forward |
| **抉择 QTE（choice-beat）** | 限时/限信息的剧情抉择，倒计时可见（不焦虑） | 现行 choices 卡 + 日历锚倒计时 UI |
| **聚力一击（charge-beat）** | 突破异象/名场面终结技：复用五行灵气珠节奏小游戏 | 突破三段式"冲关"引擎（roadmap 周期二·五） |

**与锚-帆模型咬合**（pacing-design）：硬锚的高潮幕 = beat 密集的演出段；日历锚到期的兑现 = 一段开场演出；
地点锚/大件首秀 = 一段"获取演出"。**演出不改编排，只把编排好的拍点拍得好看、可操作。**

## 五、据点首次抵达演出（打样目标 = 嘉元城，并回填七玄门）

> 关联待定 F（据点代入感）。用户痛点原话："去了嘉元城没感觉到和在七玄门有什么区别。"
> 根因（已核定）：**早期据点仍用老的扁平 explore.js**（一张图+可点的点），未上箱庭节点图、无抵达演出。

**对策（演出系统的第一个打样）**：
1. **据点节点图**：把据点迁到箱庭 L1 同款"节点图引擎"（exploremap.js），但用**据点风味**配置——
   嘉元城=朱门高墙/市集喧腾/帮派暗桩；七玄门=演武厅/药庐/后山。各据点**地标不同、风物不同**，
   一眼分得出"我在哪座城"。（大世界仍可一张图+可去的点——用户已认可，只重做据点。）
2. **首次抵达 cutscene**：进据点放一段定场演出（镜头扫地标 + 一句风物旁白 + 环境音/bgm），
   `once` 触发，复访跳过。嘉元城那段"街市喧腾、车马如流，比山下集镇繁华十倍"现成台词，配镜头即成。
3. **据点是活的**（便宜的代入感大杀器，world-architecture 已立"回访差异=世界活着的证据"）：
   per-据点**动态告示板/风物**随事件变（野狼帮残部、物价、季节）——不是新系统，是把既有 flag/涟漪链
   投影到据点界面。

**打样顺序**：先嘉元城（用户钦点的"没区别"现场）跑通**节点图 + 抵达演出 + 一段交互 beat**，
你目检体感提升后，再回填七玄门据点。

## 六、工程落点（不破坏现有契约）

- **新文件** `js/cutscene.js`：演出推进器（解释 `text:[]` 里的演出原语，调度 cam/actor/fx/sfx/wait/beat）。
  纯调度，特效委托 FX、声委托 audio、立绘委托 Art、镜头复用箱庭镜头工具——**cutscene.js 不画像素**。
- **渲染挂载**：复用 ui.js 剧情卡容器；演出层叠加一块 FX canvas（FX.ensure(host) 已支持任意 host）。
- **向后兼容**：未含演出原语的旧 stage 走原渲染路径，零回归。`node test/journey.test.js` 必须仍全绿。
- **可跳**：全局"快进"按钮跳到当前段末；`wait:auto` 拍点自动推进；复访整段可跳。
- **存档**：演出是瞬态、不入存档（与现行剧情卡一致）；`once` 抵达演出用 flag 记已播（沿用 `firedFortunes`/flag 同款）。
- **模块序**：cutscene 依赖 FX/audio/art，置于其后、ui 之前（index.html 脚本序同步）。

## 七、验收

- 嘉元城：抵达即一段定场演出（镜头+风物+声），与七玄门**一眼不同**；目检体感"到了另一座城"。
- 一个高潮幕（候选：夺丹 hf_duodan 叶师叔灵压压场 / 暖阳宝玉重逢）跑通**镜头+立绘入退场+特效+一段交互 beat**。
- 旧剧情卡零回归（journey E2E 全绿）；低端/降级模式 fail-soft（无特效也能读完）。
- 单屏竖屏放得下、随时可跳；复访零负担。
