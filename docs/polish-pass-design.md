# 全章打磨巡礼（Polish Pass）· 双模型交叉审查方法论

> 2026-07-11 用户立项："用这种方式从第一章把剧情和设计和玩法都过一遍，打磨打磨——
> 推剧情不着急，**主要是让游戏有东西玩、好玩，不要十分钟就打完一章**。"
> 方法论源自重返天南设计稿 v2 的成功实践（`_review-cftn-v1.md`）：
> **Fable 5 审"戏"（剧情/演出/情感/设计质量）+ GPT 5.6 审"机器"（玩法/系统/时长/数值/工程）→ 交叉合并 → 用户拍板 → 实装。**

---

## 一、审什么（厚度十问——每章双审的统一标尺）

> 用户设计目标（2026-07-12 明示）：**好玩、耐玩、想肝**——钩子、build、以及**每一到两章必须有一个新系统/新玩法**。

1. **时长**：正常玩家走完本章要多少小时？主线一本道跑穿要多久？（红线：不能"十分钟打完一章"）
2. **自由度**：主线节点之间玩家有多少"自己的日子"可过？月常 loop（修炼/采药/炼药/历练/坊市/切磋）在本章有没有嚼头，还是纯点击跳过？
3. **选择重量**：本章有效选择（改变后续演出/数值/关系的）有几个？假选择（选啥都一样）有几个？
4. **Build 可玩性**：剑/丹/阵三路在本章各有什么可推的？推了有感吗（主线乘法点真的乘上了吗）？
5. **战斗张力**：本章几场战斗？有没有"背板即赢"的无脑战和"数值检查"的假战斗？克制/反制/拉扯存在吗？
6. **探索与意外**：箱庭/奇遇/涟漪/世界新闻在本章的密度？玩家会不会觉得"世界只在主线里活着"？
7. **惦记感**：本章种了什么让玩家惦记的远线？上章种的在本章有没有响？
8. **重玩价值**：换一条 build/换一批选择再玩本章，体验差异有多大？
9. **新系统节拍**：本章的"新玩法"是什么？它是真新system（改变月常/战斗/决策结构）还是换皮内容？与上一章的新系统间隔是否 ≤2 章？（例：七玄门=小绿瓶+尸傀；黄枫谷=血色禁地箱庭+炼丹+筑基渡劫+洞府……逐章点名）
10. **肝点质量**：本章有什么值得反复投入的循环（可肝的）？肝的回报曲线是否诚实（投入→可感变强，无签到焦虑/无体力条——嗑瓜子铁律不破）？

## 二、怎么审（流程固化）

1. 两路后台并行：**Fable 5**（读 story/演出/账本/命途+厚度八问 1/3/6/7/8）+ **GPT 5.6**（读 engine/combat/balance/月常代码+厚度八问 1/2/4/5/8），各交 P0/P1/P2 清单（位置+问题+依据+最小改法+预估工程量）。
2. 主 agent 交叉合并：一致项直接吸收、冲突项列拍板、伪问题剔除（附理由）——产出该章《打磨清单》入 `docs/polish-XX.md`。
3. 用户拍板 → 按清单实装 → 全量回归 + 430×932 实测 → 下一章。
4. **红线**：考据已两轮核定不再翻（除非审出新硬伤）；乘法律（不加新系统，让旧系统相乘）；改数值必跑 bal 套件；每章清单单独提交。

## 四、参考基准

- 对标：觅长生的"真实修仙感"（用户口径）——日子要能过、每月有小正反馈（嗑瓜子）、选择有重量。
- 依据档：gameplay-template（节点质量）/retention-design（爽文契约）/pacing-design（锚-帆）/multiply-design（乘法）/build-balance-design（三路）/playtest 存档与报告（实测时长的地面真值）。
