# 大战场团战 · 箱庭轴 + 镜头导演 · 设计方案

> **⚠ v174 修订（2026-06-18，已落地·覆盖下文 §3.C/C1·C2 的"自由飞遁/疾遁"原案）**
> 用户实测后否决了一切"免费/快速位移"——理由：玩家筑基期靠 0 耗飞遁满场穿梭、敌人追不上，
> 就成了"和元婴一样"的无敌风筝；队友疾遁横越同样破坏「挡线」张力。**本作最终采用 grounded 走位**：
> - **删除 C1「飞遁·掠」**：取消玩家 0 耗串场技 + 自动入手牌 + 独立「遁」键 + `grantFeidun` 配置；
>   韩立恢复正常逐格移动（`moveCap`）靠近队友/补刀。原「风雷翅·雷遁」御雷闪仍按既有特性门槛保留（非大战场特权）。
> - **C2「驰援」改 grounded**：去掉全场疾遁（`_stepToward(s,t,W)` 全场位移 + dash fx + "弃线横越"台词）。
>   改为**复用现有配合系统**——同袍的 AI 倾向（仇恨/人格）驱动它朝吃紧处**逐格挪近**（与普通靠拢同一套 `moveCap`），
>   就近打配合；镜头照常靠 `turn` 拍跟着行动者拖过去。
> - **保留**：B1~B6 全套镜头导演（行动者跟拍/开场扫场/多战线徽标/燃点推近）、AI 跨线倾向、
>   C3 塌线重定向（锚点倒下→无主之敌循杀气改投最近活线；敌我皆走正常格、绝不瞬移）。
> - **权衡**：30 格 + 纯逐格，跨场支援偏慢（横跨~9 格需多回合）。已确认常态下每条战线各自贴身开打、
>   无需长途奔袭，故不显拖沓；若实测仍嫌慢，调整方向是**把战线摆近**或给小幅 `moveCap`，**绝不**回退到瞬移。
> - 演武入口 `?demo=palace`：皇宫三战场默认 grounded（不授玩家 blink/雷遁/腾空）；仅 `?demo=palace&climax=1`
>   的阵成决战才放满神雷+雷遁瞬移拉满特效。
>
> 下文 §3.C「C1 玩家自由飞遁」「C2 同袍驰援疾遁（一次性大步程）」及相关 P1/缺口#3·#4 描述为**历史原案**，
> 以本横幅为准。其余（战区模型 §3.A、镜头导演 §3.B、声明式 `fronts` §3.D·§5）一概有效。

> **状态：2026-06-18 草案，待用户拍板。** 出自用户增量需求——
> 「三个战场我想要的是那种 30 格大战场，就像箱庭 L3 一样，我一直左右飞遁能碰到别的战场，
> 互相协助对战，自由协作，并且队友行动的时候摄像机拖过去，保证衔接自然，战场演出效果好。
> 设计好这个方案并且列 design，保证以后复杂的团战都能做出这个效果。」
>
> 关联：`docs/palace-battle-fixme.md` 问题 B（三条战线 + 互相支援，是宣传片燃点）的**正解版**——
> 上一版用 `W:13` 把三组对位压进一屏是「妥协解」，本方案改为**真·大战场 + 镜头当导演**。
> 关联：`docs/combat-axis-rules.md`（对阵轴规则书）、`docs/cutscene-design.md`（演出）、`docs/fx-design.md`。
>
> **与旧军规的关系（诚实标注）**：规则书 v0.1 §0 军规二写「没有相机」。那是 2026-06-11 的

> 一路演进出**完整的一维滚动相机**。本方案是这条线的**收束与升格**——不是推翻一维（仍然

## 0. 一句话目标

把「一屏静镜的小擂台」升格为「**一条可巡游的长卷战场**」：30 格箱庭轴上同时开三条（未来 N 条）
战线，玩家左右飞遁自由串场协作，**镜头像导演一样跟着「此刻在行动的人」走位、拉推、回切**，
让远端战线的厮杀、跨场驰援的破空、玩家的瞬移补刀，都被镜头**自然衔接**成一段连贯的战场演出。
并且把这套沉淀成**声明式框架**，以后任何复杂团战只要「报战线」就能复刻这套效果。

## 1. 体验目标（拆解用户原话）

| 关键词 | 含义 | 设计落点 |
|---|---|---|
| **30 格大战场** | 战场长到一屏装不下，要走、要巡 | §3.A 战区模型，W 自适应到 24~30+ |
| **就像箱庭 L3** | 像 L3 轴式洞窟那样「探索格＝战斗格」的长卷 | §3.A 复用 `combat-axis-rules` L3 无缝衔接；长轴即箱庭 |
| **一直左右飞遁碰到别的战场** | 玩家能反复、低成本地在战线间穿梭 | §3.C 玩家自由飞遁（不再只靠有限神雷充能） |
| **互相协助 / 自由协作** | 跨战线支援既是机制也是演出 | §3.C 同袍驰援疾遁 + 仇恨锁线 / 塌线重定向 |
| **队友行动时摄像机拖过去** | 镜头主动跟随「当前行动者」 | §3.B 导演状态机：**行动者跟拍**（含位移跟拍） |
| **保证衔接自然** | 不跳切、不晕镜、推拉有节奏 | §3.B + §7 运镜参数（死区 / 单切 / 缓动曲线 / hold） |
| **战场演出效果好** | 开场有气势、远端看得见、燃点有镜头 | §3.B 开场扫场 + 远端多战线摘要 cue + 燃点慢镜 |
| **以后复杂团战都能做出** | 要框架，不要一次性硬编码 | §3.D 声明式 `fronts` 配置 + 引擎/UI 双端消费 |

单回合操作仍 ≤2 次点击；新团战仍是「填一张配置表」而非写代码。

### 2.2 缺口 ❌（本方案要补的）

1. **战场不够大、且要手摆**：`combat.js:301-302` W 封顶 15（`enemies≥2||boss`）。30 格无配置入口，
   单位还得一个个 `enemiesPos`/`sidesPos` 手摆——不可复用。
2. **镜头只跟「出手」，不跟「走位」**：`flushCombatFx` 只在 `fxcast`（攻击）拍 `_camPeek`
   （`ui.js:3215`）；纯移动发的是 `"move"` 拍（`combat.js:666/1684`），**镜头不跟**。
   →「队友横越半个战场去驰援」这一路**镜头是不动的**，等他打了才切过去，**衔接不自然**。
3. **跨场驰援太慢**：同袍 `moveCap` 常为 1（`combat.js:188/451`），30 格战场上横越 10 格要 10 回合——
   「驰援」沦为蜗牛爬，演出燃不起来。
4. **玩家串场靠有限神雷**：雷遁要耗神雷充能（`combat.js:143 chargeCost`），「一直左右飞遁」会很快没充能。
5. **开场没有「扫场」**：30 格三战线，开打第一眼只看得到 13 格，玩家**不知道还有另外两个战场**。
6. **远端 cue 只报「锁定目标」一个**：`_fightFarCue` 一次只显示锁定目标（`ui.js:3998`），
   另外两条战线在画外打成什么样**看不到**。
7. **没有「战线」这个一等概念**：引擎只有散装的 `enemiesPos/aggroSeed/crossSupport`，
   没有 `front` 抽象，UI 也拿不到「有几条战线、各在哪、各打到几成」来做导演与摘要。

## 3. 三大支柱 + 复用框架

### A. 大战场模型（战区 / Front）

**核心抽象：战线（front）＝ 一个我方锚点 + 一组敌人 + 一段轴区间。** 一维不变，只是更长、被分段。

- **W 自适应**：不再手填。由 `fronts` 数量与跨度推导：
  `W = 末战区锚点 + 右留白`，常见三战线落在 **24~30 格**（每战区占 ~7-9 格 + 战区间 ~3 格缓冲带）。
  仍保留 `cfg.W` 显式覆盖。
- **自动布局**：引擎按 `fronts[].at`（战区中心格）把该战区的我方单位与敌人**对称铺开**在锚点附近
  （我方略左、敌方略右，沿用现有 `enemiesPos/sidesPos` 的 clamp 逻辑），战区之间留**缓冲空地**
  （即「下半幅可站位的广场」，也是飞遁的落脚走廊）。
- **箱庭 L3 同源**：长轴即 `combat-axis-rules` 说的「探索格＝战斗格」的 L3 轴式箱庭——
  探索那条长走廊原地变战场，三处遭遇就是三条战线。叙事上＝皇宫纵深（宫门广场→丹陛石阶→大殿前）。
- **排（lane）不动**：仍是 2.5 排制（`combat.js:304`）。「战线」是**横轴分段**，不是纵轴排——
  避免与 lane 概念打架（lane 管前排/僚位挡线，front 管「这片战场」）。

### B. 镜头导演（Camera Director）—— 本方案的心脏

把 `flushCombatFx` 从「跟出手」升格为「**导演一个回合**」。导演的唯一信条沿用现有注释：
**「镜头能不动就不动」（晕镜的反义词）**——只在「该看的人不在画面里」时，才用缓动把他**接进来**。

**B1. 行动者跟拍（补缺口 #2）**
- 引擎在**每个单位行动开始**发一个轻量**回合标记拍** `{kind:"turn", actor: ref}`（player/side:N/enemy:N），
  紧接其后才是该单位的 move/cast/hurt 等拍。（`_actorRef` 已经在算，顺手 emit 即可。）
- `flushCombatFx` 见到 `turn` 拍 → 对 `actor` 调 `_camPeek`，**在他动手/位移之前先把镜头交给他**。
  于是「队友行动，镜头先拖过去」自然成立，且**移动拍也被覆盖**（镜头跟人走位，不再只跟出手）。
- 一个回合内**一人一次切镜**（沿用 `lastPeek` 去重），多拍连续演出镜头不抖。

**B2. 位移跟拍（让「拖过去」真的是「跟着走」而非「跳过去」）**
- P0（够用版）：`turn` 拍 peek 到行动者**最终位置**，距离大时走 `slow` 1.7s 缓动；
  世界层平移 + 单位 sprite 的 CSS 横滑 transition 同步进行，读起来就是「镜头随他滑过去」。
- P1（高级版·真跟拍）：移动拍带上 `{from:起格, to:落格}`；导演把一次长横越拆成
  **起格 → 落格两段缓动**（先把镜头落在他起步处，再跟着他平移到落点），
  跨场驰援的「这一路破空」就有了真正的**横移长镜头**。

**B3. 开场扫场（补缺口 #5）**
- 战斗一打开（`openCombat` 后），若 `fronts.length≥2`：放一段**建立镜头**——
  从最左战区缓推到最右战区（每战区停 ~0.5s 给个「这里有一摊」的印象），再回落到玩家所在战区。
- 一次性、可跳过（点屏即停回玩家）。让玩家**先读懂整个战局有几摊**，再开打。

**B4. 优先级（谁该占镜头）**——冲突时的仲裁，从高到低：
1. **燃点拍**（终结一击 `slay` / 大招 `ult` / 跨场驰援落点）→ 短暂强占 + 可选轻微推近/慢镜。
2. **玩家自身行动**（你的回合、你的锁定目标）。
3. **当前行动者**（B1 跟拍）。
4. 缺省 → 回到玩家战区（回合演出散场，`flushCombatFx` 结尾已有 `_camPeek(c,"player")`）。

**B5. 远端多战线摘要（补缺口 #6）**
- 把 `_fightFarCue` 从「只报锁定目标」扩成「**报所有画外战线**」：
  画框左/右边缘各显示一枚**战线徽标**——`左 ◀ 刘靖×血侍甲 72%` / `右 钟卫娘×血侍丙 危! ▶`，
  点徽标＝把镜头切到那条战线（手动巡场）。让玩家**永远知道另外两摊打到几成**，不靠盲猜。

### C. 自由协作 / 跨战场互援

**C1. 玩家自由飞遁串场（补缺口 #4）**
- 在**大战场（多 front）语境**下，给玩家一档**低成本横越**：
  - 方案 a（推荐）：常态「**飞遁·掠**」——一个 0 神雷、走主行动的位移技，一次掠过 ~半个视口（如 5~6 格），
    无视挡线（空层掠行），但**落点不在敌身边时不附带攻击**（纯转场）。神雷雷遁仍是「瞬移全场 + 接技」的高配。
  - 方案 b：大战场下 `moveCap` 基线提一档（如踏云靴/风雷翅时代 move 2→在 front 战场算 3），让走位够得着邻场。
  - 取舍：a 更可控、与「飞遁串场」叙事贴合，且不动平衡数值；b 改动小但会波及所有战斗的走位手感。**倾向 a。**
- 镜头：玩家飞遁＝玩家自身行动（B4 优先级 2），死区跟随自然把镜头带过去。

**C2. 同袍驰援疾遁（补缺口 #3）**
- 复用现成 `crossSupport`（`combat.js:1627-1689`），但把「横越」从 `moveCap`（1 格/拍）升级为
  **驰援疾遁**：触发驰援时该侧位获得**一次性大步程**（御剑/纵跃，覆盖到目标战区，类似玩家飞遁），
  当回合「横越 + 接战」一拍完成（或横越占一拍、下一拍接战，看距离）。
- 演出：横越发 `move{from,to}` 拍（喂 B2 跟拍）+ 现有驰援台词（「我来接应！」）+ 落点一记破空 fx。
- 触发面拓宽：不止「友方血<50%」，可加「**某战线敌我数量失衡**」（如某战线我方清完、邻场 2 打 1）也触发支援，
  让「自由协作」覆盖更多局面（仍保留「自己这条线没清完不许跑」的约束，避免全员乱窜）。

**C3. 仇恨锁线 / 塌线重定向**
- 开场 `aggroSeed` 锁三组对位（已成立）。
- **塌线重定向**：当一条战线一方被清空，存活方**自动并入最近的、仍在交火的战线**（重算 `aggroTarget`），
  战场从「三摊」动态收束成「两摊→一摊」，导演镜头随收束聚焦——团战的**自然推进感**。

### D. 复用框架：声明式 `fronts` 配置

**这是「保证以后复杂团战都能做出这个效果」的兑现**——未来团战＝填一张 `fronts` 表。

```js
// engine.js startSantuanFight（示意）
this.openCombat({
  player: hanli,
  sides:  [liujing, songmeng, zhongweiniang],
  enemies:[xs("a"), xs("b"), xs("c"), xs("a"), xs("c")],
  // —— 一等概念：战线 ——
  fronts: [
    { ally: "side:0", enemies: [0],     at: 4,  name: "宫门·左" },   // 刘靖 × 血侍甲
    { ally: "player", enemies: [1],     at: 15, name: "丹陛·中" },   // 韩立坐镇中场
    { ally: "side:2", enemies: [2, 3],  at: 26, name: "大殿·右" },   // 钟卫娘 × 双血侍
  ],
  crossSupport: true,           // 跨场驰援（默认随 fronts≥2 自动开）
  director: { establish: true } // 开场扫场（默认随 fronts≥2 自动开）
}, meta);
```

引擎消费 `fronts` 时**自动**完成（全部可被显式字段覆盖）：
- 推导 `W`（容纳所有 `at` + 留白）。
- 按 `at` 把各战区的 `ally`/`enemies` 对称落位（生成等价的 `sidesPos`/`enemiesPos`）。
- 生成 `aggroSeed`（每战区敌人锁定本战区 `ally`）。
- 开 `crossSupport` + 暴露 `c._fronts`（含每战线存活/血量摘要）给 UI 做 B5 摘要与 B3 扫场。

UI 消费 `c._fronts`：开场扫场（B3）、画外战线摘要徽标（B5）、点徽标巡场。

> **复用性自检**：墨蛟战（1v1+同道）不填 `fronts` → 走老路（零回归）；
> 未来「魔道争锋·乱星海群傀儡战」想要五条战线 → `fronts` 填 5 条即可，导演与驰援全自动复用。

## 4. 引擎落点（精确改动清单）

> 原则：**加字段、加事件、加导演调度**，尽量不改既有结算；老战斗不填新字段＝行为零变化。

**`js/combat.js`**
1. 构造器（~296-356）：解析 `cfg.fronts` → 推导 `this.W`、生成 `sidesPos/enemiesPos/aggroSeed`、
   置 `this._fronts`（战线元数据）、`crossSupport` 默认随 `fronts≥2` 开。
2. 行动调度（`startRound`/`_sideActOne`/`_enemyAct`/玩家行动）：每个单位动作开始 `_emitFx(ref,"turn",null)`
   （或新 `_emitTurn(ref)`）——喂 B1。`_actorRef` 已在算，复用。
3. 移动拍升级：`_emitFx(ref,"move",null)` → 带 `{from,to}`（`_stepToward`/`playerMove`/驰援横移处）——喂 B2/P1。
4. 跨场驰援疾遁（1672-1689）：触发时给一次性大步程；横越发 `move{from,to}` 拍。
5. 玩家飞遁·掠（C1·方案 a）：新增一个 0 耗、走主行动、无视挡线的横越技（`combat-arsenal`/`world.js` 配表，
   引擎走位逻辑复用 `_blinkTurn` 的「无视挡线」与 `canMoveTo` 放宽）。
6. 塌线重定向（C3）：战线清空时存活方 `aggro` 并入最近交火战线。
7. 维护 `c._fronts` 每回合摘要（存活数 / 血量 / 是否告急）供 UI。

**`js/ui.js`**
8. `flushCombatFx`（3205-3319）：识别 `turn` 拍 → `_camPeek(actor)`（B1）；保留 `fxcast` 兜底；
   `slay`/`ult`/驰援落点走燃点优先级（B4）。
9. `_camPeek`（4637-4673）：支持 `move{from,to}` 两段跟拍（B2/P1）；导演优先级仲裁（B4）。
10. 开场扫场（B3）：`openCombat`（2791-2888）后若 `c._fronts.length≥2` 跑建立镜头（可跳过）。
11. `_fightFarCue`（4675）→ 多战线摘要徽标 + 点击巡场（B5）；读 `c._fronts`。
12. 宽轴分支（3945）阈值与缩放：确认 `W=30` 下 `V=13` 巡游、zoom 下限 0.72 的观感（必要时给「大战场」
    再留一档微缩或保持——见 §7）。

**配置/内容**：`engine.js` 三场皇宫战改填 `fronts`（§5）；`world.js` 飞遁·掠条目（若走 C1·a）。

## 7. 「衔接自然」的运镜参数（演出手感的旋钮）

| 旋钮 | 现值 | 建议 | 理由 |
|---|---|---|---|
| 视口 `V` | 13 | 13（不变） | 单位可读性优先；大战场靠巡游不靠缩 |
| 死区 `m` | 2.4 | 2.4（不变） | 玩家中段自由走，镜头不抖 |
| 切镜缓动 | <5 格瞬移 / ≥5 格 1.7s | 跟拍统一用缓动（短距 ~0.6s、长距 ~1.5s ease-in-out） | 「拖过去」要看得见过程，不要硬跳 |
| 每回合切镜次数 | 一人一次 | 一人一次（不变） | 反晕镜铁律 |
| 行动者 hold | 无显式 | 切到行动者后 hold ~0.4s 再演下一拍 | 给「这是谁在动」一个读秒 |
| 开场扫场 | 无 | 每战区停 ~0.5s，总 ~2s，可跳过 | 建立全局认知，不拖沓 |
| 燃点推近 | 无 | `slay`/驰援落点可选 +5% 推近 + 轻慢镜 | 燃点强调，别滥用 |

> 这些都是 `_camPeek`/`flushCombatFx` 里的常数，集中成一个 `DIRECTOR` 参数对象便于调。
