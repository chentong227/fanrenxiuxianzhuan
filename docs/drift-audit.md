> 2026-06-29 创建。目的：在立宪（constitution.md）与上门禁（audit-gate.md）之前，
> 先照一次镜子——把「设计文档里写了、代码里没接（或接歪）」的缺口列清楚。
> **这份是体检报告，不是设计稿。** 它的产出直接决定宪法该重点防什么。

## 〇、一句话结论

**游戏的引擎（月回合 / 据点 / 旅途 / 因果账本 / 命途模拟）是健康的，
真正的病灶是「写入多、读出少」与「文档多、约束少」——
系统都建了，但它们之间该相乘的地方没相乘，文档之间该有的优先级没确立。**

这正是「前后不一致、数值不平衡的怪胎」的成因：不是缺零件，是零件没接线、没人管接线规范。

## 一、最严重漂移：因果账本「只记账、不结算」

### 文档承诺（world-architecture §3 / open-world §第3层）
- 因果账本是自由度的核心引擎之一。
- **设计三律**：变数插曲必有「近响 + 远雷」——种因当场有小反馈，**主线节点处必兑现大后果，且点名出处**。
- 「同一个燕家堡，因为你之前的选择，变成完全不同的战斗」。

### 代码现实（已核对）
- `Engine.writeLedger(...)` 全仓被调用 **~40+ 次**（story.js 大量、engine.js 大量）——**种因到处都是**。
- `Engine.readLedger(...)` / 真正读账本来分叉的地方 **只有个位数**：
  - `modao_e1_chen_forgot` / `modao_e1_chen_remember` 一对（chen_wangchen 分叉）
  - `yanjia_reunion` 读 chen_remember 给一囊疗伤丹（近乎纯叙事）
  - `wan_friend` / `zhuji_dan_grudge` 的 `settleLedger`（点名兑现，做得对）
  - 羁绊援助 `_npcNearby` 读 A.ledger（边角）
- **绝大多数 writeLedger 的 id 从此再没被读过**——种了因，永远不结果。

### 漂移性质
**写读严重不对称（写:读 ≈ 40:5）。** 账本沦为「成就日志」，没成为「分化引擎」。
玩家做的大量选择（村里偷干粮、路上教张铁、暗修期试探墨大夫……）写进了 ledger，
但没有任何未来节点因此不同——**违反「变数必有远雷」**。

### 严重度：★★★★★（这是「做啥都不重要」体感的直接技术根源）

### 实测复核（2026-06-29 · `test/ledger.audit.js` 静态扫描全仓）
本节估计「写:读 ≈ 40:5」是手数的保守值。机器审计实测更重：
- **种因 134 个唯一 id，仅 7 个闭环 → 闭环率 5%。**
- 闭环的 7 个：`chen_remember` / `chen_wangchen` / `jindi_seat` / `met_chen` /
  `wan_friend` / `wan_hunt_together` / `zhuji_dan_grudge`——全是 drift-audit 已点名的「正确样板」。
- 其余 127 条只记不结，且**可分两类**（这是审计带出的新洞察，决定还债策略不同）：
  - **A 类·选择债（铁律3 正主）**：玩家真金白银的取舍写了 ledger 却无人读——
    `dongfu_lingquan`/`dongfu_pijing`（洞府选址）、`village_provisions`/`village_inquiry`（离家）、
    `identity_study_poison`/`identity_practice_medicine`（墨大夫身份）、`secret_cultivate_probe`/`push`、
    `showdown_prep_martial`/`poison`……**这些是「做啥都不重要」的代码实锤，应优先补兑现窗口。**
  - **B 类·成就误占命名空间**：`*_won` / `*_slain` / 多数 `modao_*`/`starsea_*`/`zaibie_*`
    战斗战报——几乎都同时调了 `addMilestone`。按铁律3 例外条款，成就型留痕「可只记不结，
    但不得占 ledger 命名空间，走 addMilestone」。这批要么是未来篇章钩子（等内容兑现），
    要么纯属重复记账，**还债策略 = 评估后降级（删 writeLedger 保留 addMilestone）或补未来读取**。
- 已铺 `test/ledger.baseline.json`（127 条存量豁免）+ 棘轮门禁生效：**存量宽限、新债即刻 FAIL**。
  从此「只许还债、不许欠新债」，baseline 清空之日 = 本漂移治愈之时。

### 还债进度（持续更新）
- **2026-06-29 v232~233**：审计工具加 A/B 自动分类（种因点 ±260 字符内伴 `addMilestone` → B 成就债，否则 A 选择债）——
  127 条债自动切成 **A 选择债 47 / B 成就债 78**，把「一坨债」变成有策略的施工图（A 优先补兑现、B 评估降级）。
  已还 2 组 4 条选择债做范式样板：**洞府选址**（`dongfu_lingquan`/`dongfu_pijing` → modao_conscript 强征时点名兑现：藏拙挡不住军令／苦修换赴战底气）、
  **决战前准备**（`showdown_prep_martial`/`showdown_prep_poison` → showdown 反杀墨大夫时点名兑现：磨剑成快剑／备毒耗垮铁奴）。
  闭环率 **5% → 8%**（7 → 11 条）。还债工作流（补 settleLedger → 从 baseline 删 id → 审计全绿）已跑通两轮。
- **2026-06-29 v234**：再还 1 组 2 条——**离家准备**（`village_provisions`/`village_inquiry` → exam 入门选拔 onArrive 点名兑现：
  偷揣的干粮撑过补考半年／向三叔打听的门道临场对得上）。注意：这两条原已有 flag 层叙事钩子（journey/exam 读 `s.flags.village_*`），
  但 **ledger 层从未闭环**——印证审计盲区洞察：「flag 兑现了叙事 ≠ ledger 闭环」，二者需都补。闭环率 **8% → 10%**（11 → 13 条）。
  baseline 经 `--write-baseline` 重生成为 121 条（干净态，已还 6 条全部移出）。

> **还债节奏**：每轮 2~6 条选择债，优先还「玩家性格/准备类」A 类债（开局谨慎链已基本闭环：
> 离家准备→入门选拔、决战准备→反杀、洞府选址→强征）。后续优先攻 `secret_cultivate_*`/`identity_*`/`intro_*`/`friends_*` 等剩余 A 类。
- **2026-06-29 v235**：七玄门篇 A 类选择债批量闭环（8 条）——
  拜师初（`intro_observe_herbs`→以下克上·丹毒根基／`intro_watch_modafu`→反杀夜·早识杀机）、

## 二、闭关「专修方向」缺位（Build 分化第一层）

### 文档承诺（open-world §第1层·P0 / roadmap 阶段3）
- 闭关弹窗应有「专修方向」选择：苦修剑诀 / 参研丹道 / 参研阵法 / 纯修灵力。
- 核心约束：**同一个月只能推一条轴**——练剑就练不了丹。
- 被标为「零成本 P0」「足以让重开一局产生显著差异」。

### 代码现实（已核对 `ui.js openSeclusion` + `engine.js cultivate/refineLayer`）
- `openSeclusion()` 只有**时长选择**（1/6/12/36 月 + 一键到圆满）。
- `refineLayer()` 存在，但只能推**主修功法**一条层数轴——**没有剑/丹/阵的方向分叉**。
- `cultivate()` 不接受 `direction` 参数；丹术/阵法熟练度轴根本不存在（`s.skills` 只有 alchemy/scouting/fulu，且 alchemy 是采药副产物，不是闭关专修产物）。

### 漂移性质
**P0 设计未实装。** Build 路线分化（自由度的另一半）只有功法层一条线，
「这一把走剑、下一把走丹」的重玩性来源不存在。

### 严重度：★★★★☆

## 三、时间窗口互斥几乎为零（自由度的「真取舍」层）

### 文档承诺（open-world §第2层·P0 / pacing §三）
- 2~3 个日历锚窗口**重叠**，玩家只够赶一个 →「去太南就回不了乡」。
- 这是凡人对标法环「空间顺序自由」的杀手锏（时间维度取舍）。

### 代码现实（已核对 story.js cond 结构）
- STORY 节点的 `cond` 基本是**顺序 flag 链**（前一个 done → 后一个亮），偶有 `skipIf`。
- 仅有单点倒计时（`xianhui_due` / `xueshi_due`）——是「等待期」不是「互斥期」。
- **找不到一处「两个锚窗口重叠、做了 A 就永久关闭 B」的结构。**

### 漂移性质
**P0 设计未实装。** 自由停留在「选项顺序」层（伪自由），没到「取舍」层（真自由）。

### 严重度：★★★★☆

## 四、NPC 命途与玩家选择「不交叉」

### 文档承诺（open-world §第5层 / fate-design §0）
- 命途道岔应**共享同一资源池**：「同一批珍稀药材，你不够给两个人，救谁是真选择」。
- npcsim 的世界变迁应被玩家行为扰动。

### 代码现实（已核对 npcsim.js / interactions.js）
- `NPCSIM.tick()` 完全自洽地推进背景修士生死，**不读玩家任何资源/选择**。
- `INTERACTIONS` 用 relations 做好感与回赠，但**没有「救 A 就没资源救 B」的互斥资源池**。
- 命途道岔（陈巧倩 / 厉飞雨等）目前各走各的 flag，不竞争同一批 inventory。

### 漂移性质
**设计未实装。** 世界是「活的盆景」（好看但隔绝），没成为「与你抢资源的活世界」。

### 严重度：★★★☆☆

## 五、分级制平衡方案「待拍板」，旧「好招」base 仍在

### 文档现实（redesign-master.md）
- 用户已钦定：「没有所谓好招，招式法宝就是有级别的」→ 统一 `tier` 制方案。
- 文档状态明写：**「待用户审阅拍板。拍板前不动代码。」**

### 代码现实
- `balance.js spellPower` 仍是旧公式，金光砖等仍靠**拍脑袋 base 值**模拟「好招」。
- tier 字段未落地。

### 漂移性质
**这一条不算「漂移」，是「待决」**——但它是数值一致性的定时炸弹：
在它拍板前每新增一个法宝/招式，都是在用旧的「拍 base」方式制造未来要返工的债。
**宪法必须就「未决期间新内容怎么定数值」给出临时铁律，否则债越滚越大。**

### 严重度：★★★☆☆（潜伏型，越拖越重）

## 六、文档治理漂移：70+ 份平级，无优先级、无「主从」

### 现实
- `docs/` 下 **70+ 份设计文档**，`AGENTS.md` 列「必读档案」是**清单**（去哪查），
  不是**宪法**（冲突听谁）。
- 已发现实质冲突先例（AGENTS.md 自己记录）：妖材代工地点「魔道·燕家堡」vs「黄枫谷」
  冲突、欧阳飞天线混入、陈巧倩筑基误写……——**都是「无单一权威源」的产物**。
- redesign-master（待拍板）与 balance-master（已实装 A2）对数值的口径并存，没人声明谁压谁。

### 漂移性质
**治理结构缺失。** 没有「冲突时以本文件为准」的定盘星，新内容必然继续各自为政。

### 严重度：★★★★☆（这是「怪胎」的元凶——前五条都是它的症状）

## 九、给「游戏性提升」讨论的预埋观察

> 用户下一步想讨论「游戏还不够好玩」。这里先埋三个由本次盘点得出的、与「好玩」直接相关的判断，供届时展开：

1. **「不够好玩」的头号嫌疑 = 选择没有重量**（漂移 #1 的体验face）。
   玩家每个月做的事（采药 +1 药理、切磋 +1 体魄、对谈 +好感）**结算即终结**，
   不向未来延伸、不改变任何后续节点 → 大脑判定「做啥都行 = 做啥都不重要」→ 只想推主线看剧情。
2. **嗑瓜子（近反馈）做得好，但「中/远惦记」与「近反馈」之间缺乏因果链**——
   节拍器三层惦记栏是「并列展示」，不是「这一月的选择喂养了哪个远期目标」。
3. **Build 单一（漂移 #2）** → 战斗最优解趋同 → 战斗从「解题」退化为「过场」。

这三条都不是「内容不够多」，是「已有内容之间没有因果与取舍的编织」——
与「自由度从哪来」是同一个根。**好玩 = 编织，不是堆量。**
