# 大世界架构（人界全图 · 总纲）

> 2026-06-11 与用户对谈。用户裁决方向：做真正意义上的大世界——整个韩立人界在一个
> 连续世界里，而非章节箱庭制。本档案回答四个此前蓝图缺失的根本问题：
> ① 剧情如何落地架构 ② 地形如何安排 ③ 主线/自由如何切换 ④ 插曲如何影响主线。
> 本档案位阶：与 roadmap 同级的总纲。黄枫谷篇起所有章节按此架构开工。

## 〇、核心论点：修仙大世界 ≠ 无缝行走

塞尔达的大世界用脚丈量；**凡人的大世界用旅途丈量**。原著从不写韩立无缝走路——
写的是"半月后，韩立到了太南谷"，是路上的劫道散修、同行的商队、破庙的夜话。
修仙世界的"大"，自古以"千里之外""月余路程"表达。

这恰是我们（文字+场景图+月轮转）架构的天然优势：别人做无缝行走要烧十年美术，
我们做"旅途"只需要：距离表 + 旅途事件池 + 场景图。**大世界对我们不是奢望，
是最适配的形态。** 但必须是分层的：

```
L0 大陆层   天南全图：州县点阵 + 路线网（看得见的远方 = 惦记）
L1 地区层   彩霞山地区 = {七玄门/药庐/后山/集镇}（现有 locations，已跑通）
L2 箱庭层   后山深处/血色禁地 = explore 走格子（已跑通）
L∞ 旅途     点与点之间不是读条，是内容（遭遇/见闻/同路人）
```

已有架构离这套分层只差 L0 和旅途系统——L1/L2 五个版本前就跑通了。
**大世界不是推倒重来，是给现有世界加一层壳。**

## 一、空间：大陆层与旅途系统

### 1.1 大陆层数据模型

```js
WORLD.continent = {
  nodes: [   // 大陆节点 = 一个地区层包（locations 组）
    { id:"caixia",    name:"彩霞山",   region:"越国", pos:{x,y}, locs:["yaolu","houshan","wuting","town",...] },
    { id:"qingniu",   name:"青牛镇",   region:"越国", pos:{x,y}, locs:[...] },
    { id:"jiayuan",   name:"嘉元城",   region:"越国", pos:{x,y}, locs:[...] },
    { id:"tainangu",  name:"太南谷",   region:"越国", pos:{x,y}, locs:[...], timed:"tainan_fair" },
    { id:"huangfeng", name:"黄枫谷",   region:"越国", pos:{x,y}, locs:[...], gated:"shengxian_ling" },
    ...
  ],
  routes: [  // 路线：距离（月）+ 险度（遭遇表）+ 路引条件
    { from:"caixia", to:"qingniu", months:1, danger:"low",  pool:"yueguo_roads" },
    { from:"caixia", to:"jiayuan", months:2, danger:"mid",  pool:"yueguo_roads" },
    { from:"jiayuan", to:"huangfeng", months:3, danger:"mid", pool:"xiuxian_roads" },
    ...
  ],
}
```

### 1.2 三条铁律

1. **全图早见，旅途设限**：大陆图从离开七玄门起就全部可见（远方=惦记，塞尔达三角
   法则的大陆版）。限制可达的不是迷雾，是**旅途成本**：练气一层走三个月山路去黄枫谷，
   会死在车骑国边境的妖兽口里——看得见去不了，才有"我要变强"的真实动机。
2. **地区永不关闭**：青牛镇到化神期也能回。章节不锁门，锁门的是"你的人生还有没有
   理由回去"——而我们要主动给理由（见第四节·回乡机制）。
3. **飞行法宝重写地图**：神风舟/御风车/风雷翅=旅途月数折减+险度降档+解锁水路/空路。
   大件链条直接兑现在"世界变小了"的体感上——筑基前黄枫谷是远方，元婴期天南是后院。

### 1.3 旅途即内容（不是读条）

启程后进入**旅途卷轴**模式（场景图+文字流+抉择）：
- 每段路抽 1~3 个事件（按 danger 与 pool）：风闻（市集听书人说魔道蠢动）/
  岔路（道旁古庙有妖气，探不探？）/ 同路人（车队蹭车省一月，但车主有秘密）/
  劫道（战斗或破财或亮境界吓退——藏拙者只能打）
- 旅途事件吃全部六轴与杂学：探知高=提前识破埋伏；药理高=救治路人结善缘；
  名声高=报字号免战（扬名的旅途红利，对应藏拙的战斗红利）
- **旅途是"许多小篇章"的容器**：燕家堡之战的"赴堡之路"、魔道入侵的"难民西迁路"，
  都是旅途卷轴的剧情化复用。

## 二、时间：锚-帆模型（主线与自由的切换律）

> 主线是锚，自由是帆。锚定方向，帆吃风量——韩立的人生本就是
> "长蛰伏（自由）+ 短爆发（主线）"，原著节奏天然适配此模型。

### 2.1 三种主线锚

| 锚型 | 触发 | 例 | 错过会怎样 |
|------|------|-----|-----------|
| **日历锚** | 世界大事年表到点 | 升仙大会（入谷后第N年）、血色禁地60年一开、魔道入侵（黄枫谷篇后期固定爆发） | 软窗口：提前有风声+催促（厉飞雨来信/官府榜文），窗口内自由到场；超窗世界自动推演出后果（大会照开、名额归他人），主线走"补救径"（更难但更香——爽文契约） |
| **地点锚** | 首次到达/再访某节点 | 进嘉元城触发墨彩环求医线；回青牛镇触发小妹出嫁 | 不去就不触发——地点锚全部可错过，错过=平行的人生 |
| **条件锚** | flags/境界/物品判定 | 筑基成功→掌门召见赐洞府；集齐丹方+主药→地火之屋开放 | 自然挂起，条件齐自动亮起（际遇栏"天命"分区常驻可见） |

### 2.2 帆（自由行动）的三重身份

自由不是"等主线的垃圾时间"，每月行动同时在做三件事：
1. **备锚**：为下一个日历锚囤资源/做功课/赶路（血色禁地开启前你在练什么？）
2. **经营**：小绿瓶/洞府/杂学/灵宠——跨章节的纵向轴，章节会完，家底永远在
3. **撞插曲**：见第三节——自由行动是插曲的唯一入口（主线播片里不掉机缘）

### 2.3 节奏配比（可调参数，写进章节模板）

- 驻地章（黄枫谷三年）：锚稀疏（年级），帆极宽——日子感
- 事件章（燕家堡之战）：锚密集（月级），帆收窄为战间隙——战时感
- UI 表达：际遇栏分「天命」（锚：亮着的、倒计时的）与「机缘」（帆：涟漪窗口、
  异闻、际遇）两区——玩家永远知道"必须做的"和"可以做的"各是什么。

## 三、因果：插曲如何改变主线（因果账本）

> 插曲不是支线清单，是世界对你的记账。机制核心：**主线节点不写死剧本，
> 写"读账本的剧本"**——同一个主线节点，账本不同，演出与难度不同。

### 3.1 插曲三档

| 档 | 占比 | 写入 | 例 |
|----|------|------|-----|
| 风闻 | ~60% | 只写见闻/图鉴/情报 | 茶肆听闻黄枫谷收徒标准（情报面纱L0+1） |
| 岔路 | ~30% | 写资源/人情/杂学 | 救治瘟疫村庄：药理+3、纹银-20、村庄立生祠（名声+） |
| **变数** | ~10% | **写主线参数（因果账本）** | 见 3.2 |

### 3.2 因果账本（flags 的正式化升级）

```js
s.ledger = {
  // 每条 = { id, t, kind, weight }——主线节点结算时按 id 查询
  saved_chenqiaoqian: true,     // 归途救陈巧倩 → 燕家堡之战陈家暗中相助（战力+1阵营）
  met_leiwanhe_early: true,     // 太南小会偶遇雷万鹤 → 大衍诀线提前一章埋线
  spared_modao_spy: true,       // 集镇放走形迹可疑者 → 血色禁地多一伙敌人（毒修早有图谋）
  yaoyuan_overharvest: 3,       // 百药园偷种超额三次 → 马师伯警告 → 巡查加严事件链
}
```

**三条设计律**：
1. **变数插曲必有近响**（当场可见小后果）**+远雷**（主线节点处兑现大后果）——
   远雷兑现时必须点名出处："多亏当日你在官道上救下的那位女修——陈家剑阵开了一角。"
   投入有形化：玩家要能回溯"这是我当年种的因"。年表自动记因果对（种因时一行，
   结果时一行，互相链接）。
2. **变数改参数，不改骨架**：主线大节点（筑基/燕家堡之战胜败大向）不被插曲翻转——
   插曲改变的是**怎么打、和谁打、付什么代价、拿多少回报**。骨架忠于动漫（考据红线），
   血肉由玩家的账本生成。
3. **负因也是内容**：放走细作、得罪马师伯，结出来的恶果不删档不卡死，
   是更难的局+更深的爽（反杀回来名声更响）——失败向前走，因果也向前走。

### 3.3 工程：现有 flags/checkStory 即账本雏形

已有 `s.flags` + `checkStory()` 条件判定 + 涟漪链，就是账本的 v0。升级为：
ledger 字段独立（语义化命名+时间戳）、主线 STORY 节点的 cond/effect 标准化读写账本、
年表因果对链接。**不是新系统，是把暗的做明。**

## 四、章节：潮汐模型（地区解锁、回访与变迁）

> 用户方向：章节=小部分地区解锁，下一章能回上一章地区。
> 我的加强版：**章节不是开新地图，是世界换潮水**。地图早就在那里，
> 章节改变的是哪里涨潮（内容密度高）、哪里退潮（密度回落但不清零）。

### 4.1 章节类型学（五模板——"许多小篇章"的量产框架）

| 模板 | 结构 | 例 |
|------|------|-----|
| **驻地章** | 一个地区涨潮，日常轴全开，锚稀疏 | 七玄门篇、黄枫谷百药园三年 |
| **旅途章** | 路线串联多节点，旅途卷轴为主体 | 离门远行（嘉元城→回乡→太南小会→升仙大会） |
| **箱庭章** | 限时封闭 explore，死亡规则特殊 | 血色禁地五日、坠魔谷 |
| **事件章** | 单节点高密度锚链，帆收窄 | 燕家堡之战、夺舍之夜（已是此型） |
| **潮汐章** | 世界状态机切换，多个小篇章悬挂其上 | 魔道争锋：天南进入战争态，坠魔谷（箱庭）/前线（事件）/西迁路（旅途）挂在战争潮里 |

魔道争锋大篇章=**潮汐章作容器+若干小篇章作内容**——正是用户说的
"大篇章由许多小篇章组成"，工程上每个小篇章选模板填数据即可。

### 4.2 退潮地区不死（地区状态机）

每个大陆节点带状态：`{ tide: "active"|"ebb"|"war"|"ruin", snapshot: {...} }`
- 涨潮（当前章主场）：全行动+全事件池
- 退潮（章节过后）：保留地标/故人/采买/家底类行动，事件池换"退潮池"
  （门派近况/故人变迁/物价随世界事件浮动）
- 变迁由 npcsim+事件总线驱动：七玄门在你走后——王门主是否压得住野狼帮残部？
  厉飞雨升了执法堂还是出走了？**回访时的差异=世界活着的最强证据。**

### 4.3 回乡机制（情感锚点，成本极低收益极重）

韩立每个大阶段应回一次青牛镇：练气期回乡（小妹出嫁·已规划）、筑基后回乡
（爹娘已老，韩家翻新，镇人敬若神明却不识）、结丹后回乡（坟前一拜，凡尘已了）。
退潮地区+npcsim 老化+一段剧情=极低成本；"修仙者眼看凡人老去"是凡人题材
独有的杀伤力——别的游戏花一个资料片做不出这一幕，我们三段文字就够。

### 4.4 天南篇潮汐表（黄枫谷起的章节排布）

```
七玄门篇(驻地·已完)
 → 离门远行(旅途)：嘉元城/回乡/太南小会/升仙大会——大陆层+旅途系统在此首跑
 → 黄枫谷篇(驻地)：百药园三年——洞府/偷种/坊市
 → 血色禁地(箱庭)：五日死局——南宫婉并肩
 → 燕家堡之战(事件)：魔道入侵前奏——因果账本首次大结算（陈巧倩/雷万鹤线兑现）
 → 魔道争锋(潮汐)：天南战争态——坠魔谷(箱庭)/前线征调(事件)/虚天殿引子(箱庭)…
 → 乱星海篇(新大陆层)：海图+岛屿点阵+船途（旅途系统换皮即用）
```
